# FlowX 用户使用手册

本文档面向产品、研发负责人、项目经理和业务协作同学，帮助你在 FlowX 中从需求录入一路推进到 AI 执行、人工评审、问题沉淀与发布。

## FlowX 工作方式

FlowX 把研发流程拆成可中断、可确认的阶段，核心目标是：

- 让 AI 先产出，再由人确认关键节点
- 每一阶段都可追溯，降低黑盒风险
- 统一管理需求、代码仓库、执行结果、审查结论

主流程是：

`工作区 -> 项目 -> 需求 -> 一条工作流（仓库准备、产品构思、设计方案、Spec & Plan、执行开发、AI 审查） -> 人工确认 -> 问题/缺陷沉淀`

普通入口的产品构思和设计方案是同一条工作流中的可选阶段；已有原型入口自动整理并接入工作流，直接复用内容。是否执行、跳过或退回，由工作流详情页当前阶段的操作决定。Spec & Plan 为必经闸门，合并原任务拆解与技术方案，产出实现边界（spec）与实现路径（plan）。

## 功能菜单

左侧导航主要有以下模块：

- `工作区`：管理业务边界与代码仓库
- `项目`：承接实际交付单元
- `需求`：录入需求、验收标准，发起流程
- `工作流`：查看和推进每条研发流程
- `测试与质量`：管理用例库、提测范围、执行轮次与 Bug 回归
- `问题项`：沉淀 AI 审查里的改进项（Issue）
- `缺陷`：沉淀明确 Bug（Bug）
- `AI 凭据`：配置当前组织共享的 Cursor / Codex 凭据
- `API Token`（设置 → `/settings/api-tokens`）：生成本机 OpenDesign / MCP 用的长期 Personal API Token（`fxpat_…`）

## 本地 Agent 与 OpenDesign

本机用 Cursor / Codex / WorkBuddy 或 OpenDesign 时，先安装再 `login`（安装器不要求预先安装 Node.js）：

macOS / Linux：

```bash
curl -fsSL https://<当前站点>/install | bash
flowx-local login
```

Windows（PowerShell）：

```powershell
irm https://<当前站点>/install.ps1 | iex
flowx-local login
```

完整说明见 **[本地 Agent](/local-agent)**。

## 快速上手

### 步骤 1：登录系统

在登录页可选两种方式：

- 账号密码登录（也支持注册后登录）
- 钉钉登录（适合企业组织身份接入）

通过登录页独立注册的账号会自动创建自己的个人组织，默认看不到其他组织的数据。由组织管理员在“组织用户”页面创建或加入的账号属于该组织，可共享组织内的工作区、项目、需求和工作流数据。

每个组织保留一名主管理员。主管理员可以在“用户管理”中给多个成员分配或收回“子管理员”角色；子管理员可以执行组织内普通管理操作，但不能编辑或移除主管理员，也不能转让主管理员权限。只有主管理员可以分配子管理员和转让主管理员权限。

钉钉组织的管理员可进入“用户管理”，点击“同步钉钉用户”批量同步通讯录成员。同步会递归读取钉钉部门中的用户并去重，但只保存用户资料和当前组织成员关系，不保存部门树或上下级关系。同步会新增或更新用户，并将已不在钉钉通讯录中的钉钉成员移出当前组织；用户账号和历史数据不会删除，但该组织下的登录会话和 Personal API Token 会失效。本地创建且没有钉钉身份的成员不受影响。使用前需为钉钉应用开通通讯录部门和用户读取权限（至少包括 `qyapi_get_department_member`），并配置 `DINGTALK_APP_ID`、`DINGTALK_APP_SECRET`。

云效自动化规则还可以调用固定地址 `/api/yunxiao-webhooks`，将原生“工作项数据”定向发送给负责人、参与者、验证者和创建者，并按 FlowX 用户去重。FlowX 会调用云效项目成员接口获取组织成员 `memberId`、云效 `userId` 和阿里云账号绑定 ID；使用个人 Token 时，管理员需要在“设置”→“云效集成”输入项目 ID、加载成员并手动关联 FlowX 用户，不使用姓名猜测。服务端需要配置 `YUNXIAO_WEBHOOK_SECRET` 和 `YUNXIAO_PERSONAL_ACCESS_TOKEN`（也兼容 AccessKey）；未匹配人员会在“未匹配人员”区域保留。接入前应填写云效 `organizationIdentifier`。通知会优先使用 Webhook 自带的工作项链接，缺少链接时根据项目、类别和工作项标识自动生成云效地址。组织管理员可以在该页面一键启用或停用通知，停用不会删除配置和历史记录。完整配置见仓库文档 `docs/yunxiao-webhook.md`。

组织管理员可以在云效集成页面清空当前组织的未匹配人员记录；该操作不会影响成员映射、已匹配投递记录或 Webhook 原始数据。

### 步骤 2：配置组织 AI 凭据（推荐）

进入 `AI 凭据` 页面，按需配置：

- `Cursor API Key`
- `Codex / OpenAI API Key`

获取入口：

- Cursor：登录 [Cursor Dashboard](https://cursor.com/dashboard?tab=integrations)，进入 Integrations，在 User API Keys 中创建 API Key。
- Codex / OpenAI：登录 [OpenAI Platform](https://platform.openai.com/api-keys)，在 API Keys 页面创建 Project API Key，并确认对应 Project 有可用 API 额度。这里需要 API Key，不是 ChatGPT 登录密码。

保存后，系统会在当前组织的工作流执行时优先使用这组组织凭据。

### 步骤 3：创建工作区并收录仓库

进入 `工作区` 页面：

1. 新建工作区（例如“支付平台”）
2. 在工作区下新增代码仓库（填写仓库名称与地址）
3. （可选）配置仓库默认分支

> 建议先把真实会改动的仓库纳入工作区，后续需求和工作流才能准确拿到上下文。

### 步骤 4：创建项目

进入 `项目` 页面，新建项目并选择归属工作区。

一个工作区下可以有多个项目；一个项目下可以有多条需求。项目详情可维护**发布版本**清单（如 `2.6.0`）并标记当前版本；普通创建的需求必须归属其中一个版本；历史未挂版本需求仍可查看和调整。

### 步骤 5：创建需求

进入 `需求` 页面，点击「创建需求」。已有 OpenDesign 等工具导出的 ZIP 时，选择 **已有原型**，按下文直接导入；也可以选择 **普通填写**，填写：

- 所属项目
- 发布版本（必填，默认项目当前版本，可改为其他已有版本；不在该表单新建版本）
- 需求标题（必填）
- 需求描述（选填，位于折叠的「补充信息」中）
- 验收标准（选填，位于折叠的「补充信息」中）
- 影响仓库范围（可留空，留空表示继承工作区默认仓库）

**项目页快捷创建**：进入项目详情，在「需求列表」标题栏右侧点击「新建需求」，弹窗已带入项目和当前版本，只填标题即可创建；也可附上不超过 20 MiB 的原型 ZIP，点击「上传原型，AI 整理」后自动整理并接入工作流，无需确认。未上传 ZIP 时，成功后仍留在项目页并显示该版本需求，便于继续录入。没有当前版本时，点击「去设置当前版本」先完成版本设置。描述与验收标准可在后续 AI 构思中完善；上传失败时保留标题和文件以便重试，也可移除 ZIP 后普通创建。

也可在 Cursor / Codex 明确说要新建 FlowX 需求（见 [本地 Agent](/local-agent)）。普通写代码不会登记。

## 从需求到交付

### 创建需求并启动工作流

1. 在需求页点击「创建需求」，选择所属项目、发布版本（默认当前版本）并填写标题；描述、验收标准和目标仓库范围均可留空。也可从项目详情只填标题快速创建当前版本需求。
2. 创建后，在需求列表或需求详情点击 `启动研发工作流`；已有活跃流程时优先继续已有流程。
3. 在启动窗口选择工作流默认 AI 执行器和本次工作流的仓库范围；不选择仓库时使用需求默认范围。启动 AI 审查时可另选工具。
4. 启动后进入工作流详情页。仓库准备完成后，按阶段推进产品构思、设计方案、Spec & Plan、执行开发、AI 审查和人工确认。

一次研发过程对应一条工作流；如需重新发起，系统会保留历史记录，并检查同一仓库范围是否已有进行中的工作流。日常操作以当前工作流详情页为准。也可以用本地 AI 一次完成创建与启动（见 [本地 Agent](/local-agent)）。

需求详情有一条活跃流程时，点击 **继续当前工作流**；有多条时，按当前状态和仓库范围逐项选择 **继续此工作流**。已完成或失败的流程通过 **查看历史** 查看产物与记录。需要并行推进其他仓库时，点击 **启动其他仓库工作流**，在启动窗口选择仓库与执行器；已有占用范围会显示，最终由服务端校验冲突。

需求列表保持紧凑，只展示标题、项目和关键状态；需求描述、验收标准、排期、仓库范围及并行流程请进入需求详情查看。

需求页的产品构思和设计方案生成均为后台任务：提交后会立即进入“生成中”，页面刷新后查看完成结果或失败原因。

### 已有原型：上传 ZIP 后自动进入流程

1. 在 **创建需求 → 已有原型** 选择项目、发布版本和 AI 执行器，上传 ZIP；发布版本默认带出项目当前版本，可改选，未选择版本时需先补齐。一句话目标可留空。项目详情快速新建也支持附加 ZIP 并带入当前版本。
2. AI 自动整理需求、验收标准与设计说明；页面展示导入进度，无需填写澄清答案、保存草稿或确认。可离开页面，后台继续执行。
3. 成功后自动进入工作流；仓库准备完成后接续 **Spec & Plan**，复用原型与设计。原型未表达清楚的事项保留在方案待澄清内容中，AI 建议不会伪装成人工确认。
4. 失败显示原因并保留原包，可在 **重试使用的 AI** 中选择 Codex 或 Cursor，再点击 **重试导入**；默认沿用原选择，无需重新上传或创建需求。凭证错误会提示检查凭证或切换 AI。缺材料时可补传 ZIP，补传重试同样使用当前选中的 AI。同路径文件替换，其余文件保留。项目工作区需配置可访问的代码仓库；流程接续失败后的重试直接复用已有整理结果。
5. 原型预览和原包下载收在 **查看原型与材料** 中。之前停在“等待确认”的导入，打开页面会自动接续，无需再次确认。

HTML 包内 CSS、图片、字体及可静态打包的脚本会用于隔离预览，首页优先打开 `index.html`。页面切换保留在原型包内，外部链接、联网请求及后端 API 不可用。源码项目不会自动安装依赖或启动；图片仅提供文件信息，PDF/Word 仅保留附件，必要内容请附 HTML、Markdown 或文字说明。ZIP 最大 20 MiB，单文件 5 MiB、解压合并后 60 MiB、1500 文件；不接受加密包、越界路径和符号链接。详见 [原型导入说明](prototype-import.md)。

### 需求变更：一句话补充，或重新走流程

在需求详情和工作流详情都可点击 **需求变更**，填写变更说明，例如“导出增加 Excel 格式”，直接选择：

- **提交变更**：继续当前流程，正式记录这次调整。后续 AI 生成、重新生成和本地领取任务都会带上变更，原始需求和已确认文档保留。
- **重新走流程**：沿用该需求、发布版本和仓库范围，重新走产品澄清、设计、方案及开发，旧流程与产物保留，不必复制需求或逐步回退。

提交按钮即表示采用该方式，无需再次确认。记录展示原文、提交人、时间和轮次，较早的历史默认折叠；提交失败保留输入，直接重试即可。

如果显示 **当前任务尚未读取最新变更**，说明现有任务仍基于先前要求。后续生成或重新领取会获取变更；正在运行的本地任务需先在原设备结束，再重新领取，平台不会远程改写 IDE 中已有上下文。

重新走流程时，仅待执行或待确认的旧轮会标记为被新变更替代，产物仍可查看；仍有云端阶段或本地任务运行时，变更会先保存为 **待启动**，结束原任务后点击 **继续启动流程**。仓库准备失败同样保留变更并提供重试，成功后可进入关联的新流程。

### 使用本地 OpenDesign 构思与设计

1. 按上文安装并 `login`。
2. MCP：`flowx_list_tasks` → bind → 提交 `prd.md` → 同一会话提交设计。
3. 网页确认设计方案后进入 Spec & Plan。

未 login 时可用网页「打开本地构思 / OpenDesign」作兜底。详见 [本地 Agent](/local-agent) 与 [OpenDesign 本地设计阶段](opendesign-design-stage.md)。

### 确认 Spec & Plan 并进入开发

设计确认或跳过后，工作流进入 **Spec & Plan** 阶段（不可跳过）：

1. 在工作流详情点击 **生成 Spec & Plan**（云端）或 **本地生成**（选择 Cursor / Codex / WorkBuddy），也可以由本地 Agent 调用 `flowx_get_spec_plan_handoff` 领取任务。三种方式都会结合仓库上下文、PRD 与设计 Artifact 产出实现边界（spec）与实现路径（plan）。
2. 生成完成后进入 **待确认 Spec & Plan**，可查看结构化文档、人工修改、确认或带意见驳回修订。
3. 确认后进入 **待执行开发**，可按需选择云端执行或本地启动（Cursor / Codex / WorkBuddy）。

如果生成失败，Spec & Plan 阶段卡片会显示 **重新生成 Spec & Plan**，可直接开始下一次尝试，无需先回退工作流。

本地生成时，Agent 使用 `flowx_upload_artifact` 上传 `spec.md` 和 `plan.md`，再通过 `flowx_submit_spec_plan` 回传结构化结果。服务端校验资料和领取时的上下文指纹后进入同一个人工确认节点；Markdown 资料不能代替结构化结果。安装脚本会写入用户级 MCP，一般不必手改。

### 启动研发工作流

可以在需求列表或需求详情里启动工作流。启动时可选本次执行的仓库范围：

- 不选：使用需求默认仓库范围
- 手动选择：只推进本次要并行处理的仓库

### 在工作流详情推进每个阶段

标题下方的 **当前任务** 显示服务器上的当前阶段、执行人、本地最近回报和下一步；切换查看历史阶段不会改变当前任务。阶段导航、当前产物和操作优先展示，需求背景、分支、统计与质量入口默认折叠，可按需展开。产物已回传并进入确认节点时，应先评审产物。

工作流阶段按实际配置和是否跳过可选阶段推进，通常是：

1. 仓库准备：同步仓库并生成代码上下文
2. 产品构思：本地产出 PRD，可跳过；设计阶段可点「重新构思」。本地继续时先看服务器上的当前阶段，这一段可选用自己的技能或 FlowX 技能；换人接手不重做已确认产物
3. 设计方案：确认设计文档与 HTML 预览，可跳过
4. Spec & Plan：AI 生成实现边界（spec）与实现路径（plan），需人工确认或驳回修订；**不可跳过**
5. 执行开发（Execution）
6. AI 审查（AI Review）：点击执行或重新执行时，单独选择本次使用的 Codex 或 Cursor CLI；可以用本地 Cursor 完成开发，再用平台 Codex 审查
7. 人工确认（Human Review）

在各阶段你可以进行的常见操作：

- 执行阶段（如“生成 Spec & Plan”“执行开发”“执行 AI 审查”）
- 确认 / 驳回（用于需要人工把关的节点）
- 人工修改（直接修正阶段产出）
- 填写意见（用于退回或指导下一轮）
- 重新构思（设计阶段时，在产品构思面板将工作流退回构思并保留设计产物）

工作流详情的“测试与质量”区提供两个并行入口：

- **出用例**：设计方案和 Spec & Plan 都确认后，点击 **生成测试用例**，进入测试设计页生成、处理并确认功能用例和冒烟用例。
- **提测**：研发工作流完成后，点击 **发起提测**，系统会带入当前项目、版本和工作流并打开创建弹框；创建完成或关闭后，返回提测管理不会再次弹出。提测页还需要选择已确认的测试设计，之后才能创建提测草稿。

AI 审查完成后，人工决策通常有三种：

进入工作流详情的 **人工评审** 阶段即可看到这些操作按钮；审查结果和代码差异也会在该阶段继续展示。
需要调整审查结论时，可在同一阶段提交修改意见给 AI，或点击 **人工修改** 编辑审查结果 JSON 并保存。

- `通过`：工作流进入完成态
- `返工`：回到执行阶段继续修复
- `回滚`：终止当前结果并回退

开发执行完成并进入 `待 AI 审查` 后，工作流详情会直接显示 **执行 AI 审查** 和 **跳过 AI 审查**，无需先手动切换阶段。若 AI 审查因凭据、额度或其他原因无法执行，可点击 **跳过 AI 审查**；工作流仍会进入人工审核，不会自动通过。

### 多人多仓提交代码

PRD、设计与方案确认后，各成员自行开发，共用同一份文档。在 **开发执行 → 代码交付** 中，只需选择已有仓库、填写已推送的分支，然后点击 **提交分支**。平台自动读取 commit 并记录提交人及时间，不需要先领取开发任务，也不要求手填 SHA、变更文件或开发报告。

同一仓库允许多人提交不同分支，各人重新提交同一分支可更新自己的版本；不能替换其他人的提交。单次提交不会推进整个流程。每个仓库最终选择一条代表本次交付的分支；若多人在同仓开发，请自行通过 Git 完成集成后提交对应分支，平台不代替合并。

准备好后勾选各仓库交付分支，点击 **确认本次交付**。确认框会列出所选分支、完整 commit 和未纳入的仓库；本次无需修改的仓库可以不选。平台重新核对版本并读取实际代码差异，成功后进入 **AI 审查**，后续仍需人工评审与提测。分支已有新提交时，应重新提交并再次核对；不可读或没有实际差异时不会推进。分支核验不表示测试、构建或联调已通过，当前也不展示未接入的 CI 结论。

确认后的版本冻结用于审查和冒烟验证，不能通过人工编辑执行结果更换代码；需要修改时走返工或回退，重新提交新一轮分支。旧尝试可展开 **历史分支提交** 只读查看，不能直接纳入新一轮交付。分支收集中可以回退到方案阶段；本地实际任务仍需自己停止。页面读取失败可刷新重试，后台刷新保留已加载清单。

**其他执行方式与反馈** 保留原单人本地会话和云端执行。有活动的原执行任务时，先通过原入口完成或停止，避免两条完成路径相互覆盖。分支交付本身不创建运行会话，因此不出现在仅统计本地会话的研发看板中；请从需求或工作流查看。

分支交付后如选择云端按反馈返工，平台为本次所选仓库准备独立代码目录；连续云端修复沿用该范围和本地修改。仓库或分支准备失败时不会调用 AI，需要恢复分支或权限后重试。

首版仅填写分支名，不接受 PR/MR 链接。已确认的分支不再使用旧“提交并推送到远程”按钮，合并与发布继续在 Git 和现有发布环境中完成。

### 本地任务的领取与交接

本地构思、设计和 Spec & Plan 同阶段只允许一个有效执行会话。原执行人重复领取会复用自己的会话；其他人领取会提示占用，同时领取时仅一人成功。组织成员可以查看进展和评审产物，回传必须由原领取人完成。本地继续流程会读取最新已确认的上游产物，遇到他人占用时等待当前执行人回传。

**已领取，待本地回报** 不代表 IDE 已启动。没有真实回报时显示 **尚未确认本地运行状态**；长时间未回报也不代表原设备已停止。缺少执行人记录时显示 **未记录执行人**，不会自动归给打开页面的人。

构思、设计或 Spec & Plan 的旧本地任务需要换人时，原执行人或同组织管理员可点击 **结束本次本地任务**。先在原设备停止任务，再勾选确认并填写交接原因；无执行人记录的历史任务只能由同组织管理员处理。此操作仅结束平台会话，不能远程关闭 IDE。旧尝试保留失败与交接记录，下一人重新领取新的尝试，旧会话不能再回传。会话取消后也不能通过通用上传、事件或状态接口追加旧结果；新设计稿记录原执行会话，未记录执行人的历史稿只读。开发等支持协作式控制的任务仍需停止请求与本地回执，不能通过此入口绕过。

## 研发看板

进入系统后默认打开“看板”，也可通过左侧首项进入。顶部展示四张数量概览卡，点击卡片切换下方任务范围；下方以响应式任务卡片集中查看多条需求并行开发的情况。这里聚合本地开发执行，不包含产品构思、设计、Spec & Plan、云端执行和测试轮次。开发、启动及其他操作继续在本地完成。

- **进行中**（默认）：等待本地执行、开发执行、阻塞和提交结果中的任务，异常优先展示。
- **需关注**：阻塞、执行失败、等待本地确认停止，以及受控会话超过 5 分钟没有检查点的任务。
- **已完成**：已经回传完成结果的任务。
- **全部**：包含已取消任务在内的开发执行历史，异常优先，同类按创建时间倒序。

顶部数量按当前组织及项目、执行人、工具、需求名称搜索的完整范围统计，不受页码、当前视图和精确状态影响；“进行中”和“需关注”可能重叠，不应相加。

可以组合项目、执行人、工具、精确运行状态筛选，并按需求名称搜索；点击概览卡切换视图时清除精确状态筛选，避免范围冲突。列表每页 **20 条**，底部显示总条数、当前页和总页数，支持上一页、下一页及页码切换。修改筛选或搜索回到第一页；刷新、打开详情再返回时保留当前筛选和页码。筛选条件可以通过页面 URL 分享。旧 `/execution-sessions` 列表链接会保留查询条件跳转到 `/dashboard`，原详情链接仍可访问；从需求或工作流链接进入并登录后，仍返回原目标及其查询条件。

任务卡片展示需求、项目、执行人、Agent、当前执行状态、最近进展、持续时间、最近检查点和已回传的测试摘要。阻塞和失败直接展示原因。最近进展来自 `execution.progressed` 的 `payload.summary` 或 `payload.message`、会话摘要或阶段状态摘要；完成任务优先展示完成摘要。没有具体内容时显示“暂无进度回报”或“暂无完成摘要”，不会把心跳解释为开发进度，也不会推测完成百分比。持续时间从启动时间计算，尚未启动时从会话创建时间计算；终态停止累计。看板只汇总已有回报，不会自动采集 IDE 的对话和代码操作。

列表每 30 秒自动更新，后台刷新保留当前内容；刷新失败时仍可查看已有结果并重试。点击“查看进展”进入只读详情：

- **当前进展**：查看当前状态、最近的具体进展、阻塞原因、执行人和持续时间。
- **最近进展**：展示最近同步的进展正文及状态变化，按时间倒序最多显示 10 条；服务端先排除普通心跳等非进展记录再分页，并与单独获取的最新进展合并，较早的真实进展不会被大量心跳挤掉。没有具体回报时明确提示尚无记录。
- **开发结果**：按开发摘要、代码提交、变更文件、测试、构建、远端分支检查及人工确认分类展示。提交记录包含已有分支、提交 SHA 和本地回报的推送标记，变更文件可以展开查看。
- **技术信息**：默认折叠，包含设备、检查点时间、会话和追踪标识，便于排查同步问题。

“本地回报”表示 Agent 已提交该记录，“已核验”和“核验未通过”表示该记录的核验状态；这些标签不代表测试是否通过，测试和构建结论以各自回报内容为准。原“完成证据”在独立详情中改为上述开发结果分类，仍在开发中或结果尚未回传时会给出说明。读取失败与确实无结果分别提示，刷新失败保留已有内容；页面顶部可刷新重试。可以通过“打开工作流”回到需求的完整产出与审查。

本地 Agent 可通过 `flowx_execution_checkpoint` 的可选 `progressSummary` 回报实际进展。需要使用新版 `flowx-local` 并重新加载 IDE 的 FlowX MCP/执行技能；旧客户端仍能使用普通检查点，但没有具体摘要时页面不会推测进度。

### 检查点与原有运行控制

工作流的执行阶段保留原有协作式控制入口。独立开发进展详情以查看为主。

- **在线**：最近 5 分钟内收到检查点。
- **失联**：超过 5 分钟没有检查点，只表示平台没有新回报，不表示 Cursor 或 Codex 已经停止。
- **阻塞**：Agent 主动报告等待人工处理，可由执行人或组织管理员请求恢复。
- **等待取消回执**：平台已经阻止完成提交，Agent 在本地停止任务后需要回执。

取消和恢复都是协作式命令。FlowX 不会强制终止 IDE 内进程；重新交接前必须确认旧设备上的任务已经停止。完成报告必须使用当前 handoff 的 `executionSessionId`，提交并推送后工作区干净也可以根据任务基线识别变更。

## 测试与质量

`测试与质量` 在左侧导航下展开三个子菜单，并支持从提测记录进入测试设计：

- `提测管理`（`/quality/test-requests`）：按项目和状态查看提测记录，选择项目版本下已完成的研发工作流发起提测草稿。点击记录进入详情页，可创建 Web、API、iOS、Android 等多目标端本地冒烟轮次，查看覆盖矩阵、执行人和服务端提测报告。提测前必须关联已确认且未过期的测试设计
- `用例库`（`/quality/test-cases`）：通过高密度列表、搜索、优先级和用例库筛选维护大量 Workspace 共享用例及项目专属用例。列表操作区可查看、编辑或删除用例；编辑支持调整所属用例库、模块、用例编号、标题、优先级、前置条件、测试数据、步骤、预期结果和标签，保存后用例版本自动递增，已冻结的提测快照不受影响。“模块管理”可按用例库新增、重命名、调整上级或删除模块；有子模块时需先删除子模块，删除后原模块下的用例保留并转为“未分模块”。可下载 CSV 模板，也可直接上传包含 `用例ID`、`用例标题`、`优先级`、`操作步骤`、`预期结果` 的外部 XLSX 用例表。外部表的一级、二级模块会在导入时自动创建或复用为模块层级，场景、用例类型、适用范围和追溯 ID 会转为标签；测试目的、通过标准、失败判定、自动化状态、备注及执行记录列不会导入。每次最多 1000 条；步骤按单元格换行拆分，标签按英文逗号拆分。文件会先完整校验，任何一行有误都不会写入；服务端还会检查目标库的模块和编号重复。删除用例后，它不再进入新的提测范围，已经冻结的提测快照和历史执行结果仍会保留
- `执行记录`（`/quality/test-runs`）：查看初测、本地冒烟和 Bug 回归轮次及其状态

在 Spec & Plan 确认后，可以创建测试设计并与开发执行并行。测试设计会读取 PRD、设计方案和 Spec & Plan，同时比对项目用例库及 Workspace 共享用例库，给出复用、优化、新增和不纳入建议。测试人员确认候选后，优化会递增正式用例版本，历史提测快照不受影响。

候选卡片右上角显示处理状态，操作按钮位于卡片底部。标为“AI 建议本次不测”的候选会显示不纳入原因；选择“本次不测”表示确认排除，保留用例库中的原用例；选择“按原用例复用”会以已有用例的内容纳入本次范围，仅有关联已有用例时显示。处理后状态分别为“本次不测”或“已纳入”。如果已纳入的复用候选与原用例内容不一致，它仍计入待处理，并可改为本次不测、按原用例复用或按建议优化；按建议优化会更新原用例版本。

生成测试设计会使用当前组织可用的默认 AI 执行器凭据。点击“生成候选”后任务会在后台执行，页面显示“生成中”并自动刷新；完成后进入“待处理”。失败时页面显示可安全公开的原因，按提示检查凭据、额度或服务状态后可重试；旧版本已经失败的记录需要重新生成才能显示失败原因。已有已确认用例不会因此被覆盖。

在测试设计页点击“确认冒烟”，会批量确认本次冒烟候选并更新测试设计修订号；这一步确认的是测试范围，执行结果由后续冒烟轮次记录。冒烟用例每次根据当前改动动态生成，只进入本次测试计划快照，不维护长期固定的冒烟库。一个本地冒烟轮次按“用例快照 × 目标端”展开；不同开发者和设备通过租约认领未占用分片，日志、截图、视频、JUnit 和 coverage 由本地上传，服务端保留每次执行明细并聚合当前结论。仍有有效租约、必测项缺结果或阻断项未通过时，不能生成报告。

每个冒烟执行必须由原领取人回传，其他成员不能代用其会话提交结果。不同目标端或未占用用例仍可并行执行。

范围完成且本地冒烟门禁通过后，在提测详情点击 **汇总并生成报告**。报告由服务端根据当前有效结果生成版本化 HTML，包含项目版本、目标端进度、逐例结论、执行人、设备、代码 revision 和证据；下载入口显示在提测详情。已创建本地冒烟轮次的提测会在报告生成前保持草稿状态。

尚未生成报告时，详情正常显示 **暂无提测报告**。基本信息、报告和冒烟轮次分别加载；报告或轮次加载失败不会清空已展示的信息，可在对应位置重试。基本信息加载失败时可重试详情；无权访问、提测不存在和网络错误会分别提示。

提测流程不设置“拒绝”状态。AI 生成精准范围后，系统通过用例快照、已完成研发工作流和覆盖检查确认范围是否就绪；范围不完整时保留在草稿状态。Bug 修复完成后，通过新的回归轮次记录受影响用例，不覆盖历史执行结果。

## 常见问题

### 为什么我不能直接“启动研发工作流”？

请先检查需求是否属于当前组织、工作区是否配置了可用仓库，以及同一需求和仓库范围是否已有进行中的工作流。工作流启动后，产品构思、设计等可选阶段会在工作流详情中处理，不需要提前完成额外的确认流程。

### 我配置了 AI 凭据，为什么没生效？

请确认：

- 当前登录会话选择的是已配置凭据的组织
- 页面状态显示“已配置”
- 工作流是凭据配置后新启动的（旧流程可能仍使用旧上下文）

### 独立注册的账号为什么仍能看到原组织数据？

升级组织隔离功能前，密码账号可能被自动加入当时唯一的组织。请由原组织管理员在“组织用户”页面移除该账号；账号下次登录时会自动创建个人组织，此后只能看到个人组织下新建的数据。不要移除仍需参与原组织协作的成员账号。

## 团队落地建议

建议团队按下面顺序落地：

1. 管理员先完成工作区和仓库初始化
2. 由管理员或指定成员配置当前组织的 `AI 凭据`
3. 项目负责人按项目组织需求
4. 创建需求后直接发起一条工作流，在工作流详情中按阶段确认和推进
5. 在 AI 审查后坚持人工决策与问题沉淀

这样可以把“AI 产出”和“人类决策”稳定地串成可复用流程。
