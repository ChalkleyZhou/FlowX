## ADDED Requirements

### Requirement: 项目可维护多份代码审查

系统 MUST 允许一个项目创建多份代码审查。每一份 MUST 包含项目内唯一的名称、启用状态、每日发送小时、时区，以及零个或多个仓库。系统 MUST 拒绝缺少名称或名称与同项目另一份重复的创建和更新。

#### Scenario: 创建第二份代码审查
- **WHEN** 项目已有一份代码审查，用户再创建一份名称不同的代码审查
- **THEN** 两份同时存在，各自保存自己的名称、时刻和仓库

#### Scenario: 重名被拒绝
- **WHEN** 用户创建或重命名一份代码审查，名称与同项目已有份相同
- **THEN** 系统拒绝保存，已有份不变

### Requirement: 代码审查只能选择所属工作区的仓库

系统 MUST 只接受属于该项目工作区的仓库。不属于该工作区的仓库 MUST 被拒绝。同一仓库 MAY 同时属于同一项目的多份代码审查。

#### Scenario: 选择工作区内仓库
- **WHEN** 用户把本项目工作区中的两个仓库加入一份代码审查
- **THEN** 该份只记录这两个仓库

#### Scenario: 拒绝其他工作区仓库
- **WHEN** 用户提交的仓库不属于该项目的工作区
- **THEN** 系统拒绝保存，该份的仓库集合不变

#### Scenario: 同一仓库进入两份
- **WHEN** 用户把同一个工作区仓库分别加入两份代码审查
- **THEN** 两份都包含该仓库

### Requirement: 新仓库不自动进入已有代码审查

工作区新增仓库后，系统 MUST NOT 把该仓库写入已有代码审查。配置读取 MUST 返回该份当前选中的仓库。

#### Scenario: 新增仓库保持未加入
- **WHEN** 工作区新增一个仓库，项目下已有代码审查
- **THEN** 已有代码审查的仓库集合不包含该新仓库

### Requirement: 生成只审查已选仓库

生成一份代码审查时，系统 MUST 只对应该份选中的仓库收集提交并准备审查沙箱。沙箱 MUST 使用既有的代码审查 sandbox 目录，MUST NOT 调用主开发 clone 的同步，MUST NOT 写入 `Repository.localPath`。未选中仓库 MUST NOT 出现在该份的审查单元中。仓库集合为空时，系统 MUST 保存一条说明没有仓库的生成结果。两份选中同一仓库时，系统 MAY 各自运行一次审查，并 MUST 复用该仓库已有的 sandbox。

#### Scenario: 只审查选中仓库
- **WHEN** 一份代码审查选中仓库 A，同一工作区还有仓库 B
- **THEN** 生成结果的审查单元只包含仓库 A

#### Scenario: 没有选中仓库
- **WHEN** 用户生成一份未选择任何仓库的代码审查
- **THEN** 系统保存一条没有仓库可审查的记录

#### Scenario: 重叠仓库复用沙箱
- **WHEN** 两份代码审查都选中同一仓库并先后生成
- **THEN** 两次审查都针对该仓库运行，且使用该仓库同一代码审查 sandbox，不修改仓库的 `localPath`

### Requirement: 代码审查历史按份和日期唯一

系统 MUST 以份和记录日期作为每日代码审查记录的唯一身份。对同一身份再次生成时 MUST 更新原记录。`scope` MUST 保存本次生成时的仓库快照。

#### Scenario: 重复生成更新同一条
- **WHEN** 用户对同一份、同一日期再次生成代码审查
- **THEN** 该身份下仍只有一条记录，内容为最新一次生成结果

### Requirement: 定时调度按份独立

系统 MUST 只为 `enabled = true` 的代码审查份执行定时生成，并以该份自己的小时和调度水位判断是否到期。一份生成或发送失败 MUST NOT 阻止其他份在同一轮调度中执行。关闭定时后，系统 MUST 仍允许手动生成该份。

#### Scenario: 两份在不同整点发送
- **WHEN** 两份代码审查分别设置在不同整点且都已启用
- **THEN** 每一份只在自己的整点生成并进入发送，调度水位互不影响

#### Scenario: 关闭后仍可手动生成
- **WHEN** 一份代码审查的定时已关闭，用户手动生成
- **THEN** 系统生成该份记录，且定时任务不会在未启用时自动发送

### Requirement: 投递目标按份选用

投递目标 MUST 继续属于项目。每一份 MUST 保存自己选用的目标。创建时若未指定目标，系统 MUST 连上该项目当前启用且 `forCodeReview = true` 的全部目标。发送时 MUST 只向该份选用、且当前仍启用并仍允许代码审查的目标投递。选用集合为空时 MUST 不发送，且 MUST NOT 回退为项目全部目标。

#### Scenario: 两份发给不同目标
- **WHEN** 两份代码审查分别选用项目中的不同投递目标并执行发送
- **THEN** 每一份只向自己选用的目标创建投递记录

#### Scenario: 未选用目标
- **WHEN** 一份代码审查没有选用任何投递目标并执行发送
- **THEN** 发送结果的目标数为 0，且不创建投递记录

### Requirement: 有历史记录的代码审查不可删除

系统 MUST 拒绝删除已经存在代码审查记录的份。删除被拒绝时，已有记录和配置 MUST 保持不变。没有记录的份 MUST 可以被删除。

#### Scenario: 已生成后删除被拒绝
- **WHEN** 用户删除一份已经生成过代码审查的配置
- **THEN** 系统拒绝删除，该份和它的历史记录仍可读取

#### Scenario: 未生成时可以删除
- **WHEN** 用户删除一份从未生成过代码审查的配置
- **THEN** 该份及其仓库、投递选用关系被删除

### Requirement: 不再提供工作区级排除列表

系统 MUST NOT 再提供 `CodeReviewSource` 或按仓库排除整份工作区代码审查的 API 与设置页。仓库是否进入审查 MUST 只由各份自己的勾选决定。

#### Scenario: 排除接口不可用
- **WHEN** 客户端调用原代码审查数据源排除接口
- **THEN** 该接口不再作为可用的范围控制能力提供

### Requirement: 迁移把排除仓库留在默认份之外

系统 MUST 为每个已有代码审查配置或已有审查记录的项目创建一份名为「默认」的代码审查。该份 MUST 复制原配置的启用状态、小时、时区和调度水位，并勾选迁移时工作区中未被 `CodeReviewSource.isActive = false` 排除的仓库。同一项目和日期有多条旧记录时，MUST 只保留更新时间最新的一条并挂到该默认份。

#### Scenario: 被排除的仓库不进入默认份
- **WHEN** 迁移前工作区有仓库 A 和仓库 B，且仓库 B 被代码审查数据源标记为不参与
- **THEN** 迁移后的默认代码审查选中仓库 A，不选中仓库 B

#### Scenario: 同一天的重复历史被折叠
- **WHEN** 迁移前同一项目、同一日期存在两条范围不同的代码审查记录
- **THEN** 迁移后该默认份在这个日期下只保留更新时间最新的一条
