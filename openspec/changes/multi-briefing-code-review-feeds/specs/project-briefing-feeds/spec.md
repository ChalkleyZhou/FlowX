## ADDED Requirements

### Requirement: 项目可维护多份简报

系统 MUST 允许一个项目创建多份简报。每一份 MUST 包含项目内唯一的名称、启用状态、每日发送小时、时区，以及零个或多个仓库。系统 MUST 拒绝缺少名称或名称与同项目另一份重复的创建和更新。

#### Scenario: 创建第二份简报
- **WHEN** 项目已有一份简报，用户再创建一份名称不同的简报
- **THEN** 两份同时存在，各自保存自己的名称、时刻和仓库

#### Scenario: 重名被拒绝
- **WHEN** 用户创建或重命名一份简报，名称与同项目已有份相同
- **THEN** 系统拒绝保存，已有份不变

### Requirement: 简报只能选择所属工作区的仓库

系统 MUST 只接受属于该项目工作区的仓库。不属于该工作区的仓库 MUST 被拒绝。同一仓库 MAY 同时属于同一项目的多份简报。

#### Scenario: 选择工作区内仓库
- **WHEN** 用户把本项目工作区中的两个仓库加入一份简报
- **THEN** 该份只记录这两个仓库

#### Scenario: 拒绝其他工作区仓库
- **WHEN** 用户提交的仓库不属于该项目的工作区
- **THEN** 系统拒绝保存，该份的仓库集合不变

#### Scenario: 同一仓库进入两份
- **WHEN** 用户把同一个工作区仓库分别加入两份简报
- **THEN** 两份都包含该仓库

### Requirement: 新仓库不自动进入已有简报

工作区新增仓库后，系统 MUST NOT 把该仓库写入已有简报。配置读取 MUST 返回该份当前选中的仓库，使客户端能够用工作区仓库列表标出尚未加入的仓库。

#### Scenario: 新增仓库保持未加入
- **WHEN** 工作区新增一个仓库，项目下已有简报
- **THEN** 已有简报的仓库集合不包含该新仓库

### Requirement: 生成只聚合已选仓库

生成一份简报时，系统 MUST 只使用该份选中仓库上、属于该项目工作区且处于启用状态的 `BriefingSource` 事件。未选中仓库的事件 MUST NOT 进入该份内容。选中但没有启用数据源的仓库 MUST 出现在范围快照中，且不贡献事件。仓库集合为空时，系统 MUST 仍保存一条生成结果，事件数为 0。

#### Scenario: 只纳入选中仓库的事件
- **WHEN** 一份简报选中仓库 A，同一工作区的仓库 B 在同一周期内也有简报事件
- **THEN** 生成结果只包含仓库 A 的事件

#### Scenario: 没有选中仓库
- **WHEN** 用户生成一份未选择任何仓库的简报
- **THEN** 系统保存一条事件数为 0 的简报记录

### Requirement: 简报历史按份、日期和周期唯一

系统 MUST 以份、记录日期和周期作为简报记录的唯一身份。对同一身份再次生成时 MUST 更新原记录。`scope` MUST 保存本次生成时的仓库和数据源快照。调整仓库勾选后再次生成同一日期和周期，MUST 更新该记录而不是新建另一条。

#### Scenario: 重复生成更新同一条
- **WHEN** 用户对同一份、同一日期、同一周期再次生成
- **THEN** 该身份下仍只有一条简报记录，内容为最新一次生成结果

#### Scenario: 日周报互不覆盖
- **WHEN** 同一份在同一记录日期分别生成日报和周报
- **THEN** 系统保存两条记录

### Requirement: 定时调度按份独立

系统 MUST 只为 `enabled = true` 的简报份执行定时生成，并以该份自己的小时和调度水位判断是否到期。一份生成或发送失败 MUST NOT 阻止其他份在同一轮调度中执行。关闭定时后，系统 MUST 仍允许手动生成该份。

#### Scenario: 两份在不同整点发送
- **WHEN** 两份简报分别设置在不同整点且都已启用
- **THEN** 每一份只在自己的整点生成并进入发送，调度水位互不影响

#### Scenario: 关闭后仍可手动生成
- **WHEN** 一份简报的定时已关闭，用户手动生成
- **THEN** 系统生成该份记录，且定时任务不会因为这次手动生成而在未启用时自动发送

### Requirement: 投递目标按份选用

投递目标 MUST 继续属于项目。每一份 MUST 保存自己选用的目标。创建时若未指定目标，系统 MUST 连上该项目当前启用且 `forBriefing = true` 的全部目标。发送时 MUST 只向该份选用、且当前仍启用并仍允许简报的目标投递。选用集合为空时 MUST 不发送，且 MUST NOT 回退为项目全部目标。

#### Scenario: 两份发给不同目标
- **WHEN** 两份简报分别选用项目中的不同投递目标并执行发送
- **THEN** 每一份只向自己选用的目标创建投递记录

#### Scenario: 未选用目标
- **WHEN** 一份简报没有选用任何投递目标并执行发送
- **THEN** 发送结果的目标数为 0，且不创建投递记录

### Requirement: 有历史记录的简报不可删除

系统 MUST 拒绝删除已经存在简报记录的份。删除被拒绝时，已有记录、仓库勾选和调度设置 MUST 保持不变。没有记录的份 MUST 可以被删除。

#### Scenario: 已生成后删除被拒绝
- **WHEN** 用户删除一份已经生成过简报的配置
- **THEN** 系统拒绝删除，该份和它的历史记录仍可读取

#### Scenario: 未生成时可以删除
- **WHEN** 用户删除一份从未生成过简报的配置
- **THEN** 该份及其仓库、投递选用关系被删除

### Requirement: 迁移保留现有单例简报

系统 MUST 为每个已有简报配置或已有简报记录的项目创建一份名为「默认」的简报。该份 MUST 复制原配置的启用状态、小时、时区和调度水位，并勾选迁移时该项目工作区的全部仓库。同一项目、日期和周期有多条旧记录时，MUST 只保留更新时间最新的一条并挂到该默认份。

#### Scenario: 旧配置变成默认份
- **WHEN** 迁移执行前项目有一份已启用的简报配置，工作区有两个仓库
- **THEN** 迁移后该项目有一份名为「默认」的简报，处于启用状态，并选中这两个仓库

#### Scenario: 同一天的重复历史被折叠
- **WHEN** 迁移前同一项目、同一日期、同一周期存在两条范围不同的简报记录
- **THEN** 迁移后该默认份在这个日期和周期下只保留更新时间最新的一条
