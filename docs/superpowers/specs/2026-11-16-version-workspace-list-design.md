# 版本工作台列表统一设计

## 1. 背景与目标

版本工作台目前使用一套独立的可编辑工作项表格，和需求列表的表格布局不一致，状态、负责人和备注可以直接在行内修改，执行项列也增加了当前页面的噪音。需求、问题、缺陷已经分别拥有成熟的列表接口和领域字段，版本工作台应复用这些能力，在当前版本范围内提供统一入口。

本次调整目标：

- 版本工作台保留版本切换和当前项目范围。
- 将类型下拉筛选改为 Tab，默认展示全部工作项。
- 需求、问题、缺陷 Tab 使用各自领域的专属字段和详情入口。
- 工作台列表统一采用需求列表的表格视觉，包括边框表头、固定操作列和分页。
- 状态、负责人、备注在工作台只读展示；编辑统一进入工作项详情页。
- 移除执行项列，避免把执行拆分细节带入版本浏览场景。

## 2. 交互设计

### 2.1 页面入口与版本

路由仍为 `/versions`。页面标题固定为“版本工作台”，右上角版本选择器默认显示项目当前版本。切换版本后保留当前 Tab，重新读取该版本的数据；版本配置仍通过“版本配置”二级入口进入。

版本 ID 继续通过 `versionId` 查询参数保存；新增 `kind` 查询参数保存 Tab，允许刷新和深链恢复页面状态。`kind` 的取值为 `ALL`、`REQUIREMENT`、`ISSUE`、`BUG`，缺省时按 `ALL` 处理。

### 2.2 类型 Tab

工作台列表上方显示四个 Tab：`全部`、`需求`、`问题`、`缺陷`。切换 Tab 时重置分页到第一页、清空当前列表并按新的类型重新请求；搜索关键字继续作用于当前 Tab。

`全部` 用于跨类型快速浏览，显示公共字段：类型、标题、描述、状态、优先级、负责人、更新时间、操作。它保持服务端按更新时间排序，不提供行内编辑。

### 2.3 领域专属列表

三个领域 Tab 均使用需求列表的表格容器和固定操作列，但列定义不同：

| Tab | 列 |
| --- | --- |
| 需求 | 需求标题、需求描述、优先级、创建人、创建时间、需求变更时间、最新变更内容、备注、操作 |
| 问题 | 问题标题、问题描述、状态、优先级、来源工作流、分支、操作 |
| 缺陷 | 缺陷标题、缺陷描述、严重级别、优先级、状态、来源工作流、分支、操作 |

状态、负责人和备注在工作台均以文本或 Badge 展示；不渲染 `Select`、`PagedSelect` 或可编辑 `Input`。每行的“详情”链接统一指向 `/work-items/:id`，需要修改时从详情页完成。

搜索、加载、错误、空结果和分页沿用现有列表的交互语义。空结果文案根据 Tab 变化，例如“当前版本还没有需求”。

## 3. 数据与组件方案

### 3.1 API 复用

版本工作台由页面编排当前项目、版本和 Tab；类型 Tab 复用现有分页 API：

- 需求：`GET /work-items?kind=REQUIREMENT&projectId=&versionId=`，沿用需求列表返回的需求变更和原型导入摘要字段。
- 问题：`GET /work-items?kind=ISSUE&projectId=&versionId=`，沿用问题列表的状态、优先级、来源流程和分支字段。
- 缺陷：`GET /bugs?projectId=&versionId=`，在缺陷分页接口增加 `versionId` 过滤，沿用严重级别、来源流程和分支字段。
- 全部：继续使用版本工作项分页接口，保证跨类型列表由服务端统一排序和分页；仅使用公共字段。

API 和前端请求统一使用 `projectId`、`versionId`、`q` 与分页参数，不改变已有详情、创建和更新接口。

### 3.2 前端边界

- `VersionWorkspacePage` 继续负责当前版本解析、默认版本跳转和查询参数同步。
- `VersionWorkItemsPage` 负责版本选择、Tab、搜索、加载状态和分页编排。
- 新增版本场景的表格渲染组件或局部渲染函数，复用 `ListToolbar`、`ListPagination`、`Badge`、`EmptyState`、需求列表的表格 class 和已有 label formatter。
- 不重构需求、问题、缺陷三个完整页面；只抽取真正需要共享的表格结构或展示 helper，避免影响现有页面的创建、编辑和筛选逻辑。

## 4. 后端与兼容性

缺陷列表服务在 `GET /bugs` 查询中增加可选 `versionId`，只收窄查询范围，不改变无该参数时的返回行为。问题和需求已经支持 `versionId`，无需变更其业务规则。当前版本工作项接口保留给“全部”视图，旧的项目版本工作项深链继续可用。

本次为 Web/API 查询能力扩展，不涉及 Prisma schema、MCP、CLI、Skill 或本地 Agent 协议；本地适配结论为“不适用”，因为没有新增本地调用入口或工作流状态变化。

## 5. 错误与边界

- 当前项目不存在时继续显示项目范围提示，不发起无范围的列表请求。
- 版本无效或不属于当前项目时沿用现有版本加载错误处理。
- 单个 Tab 请求失败时保留页面结构并显示可重试错误，不影响版本选择器和配置入口。
- Tab、搜索和版本切换产生的旧请求不能覆盖最新选择；请求完成后只更新当前查询对应的列表。
- 无当前版本时继续引导到“版本配置”，不自动创建版本。
