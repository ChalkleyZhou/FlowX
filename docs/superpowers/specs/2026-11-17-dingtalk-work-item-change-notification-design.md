# 工作项负责人和状态变更钉钉通知设计

## 背景

版本工作台已经支持修改需求、问题和缺陷的负责人、状态。负责人和状态变化目前只保存在工作项中，相关人员无法在钉钉中及时获知变化，也不能从通知直接回到工作项。

项目已有 `DingTalkNotificationService`，支持通过钉钉应用向 FlowX 用户发送个人 Markdown 消息，并能根据 `AuthIdentity` 解析钉钉用户身份。工作流阶段通知和云效 Webhook 通知都复用这条发送链路。本次继续复用该能力。

## 目标

- 工作项负责人发生变化时通知新负责人。
- 工作项状态发生变化时通知更新后的当前负责人。
- 同一次保存同时发生负责人和状态变化时，向同一接收人合并为一条消息。
- 消息包含工作项编号、标题、项目、变更人、负责人变化或状态变化，并提供「查看工作项」链接。
- 钉钉配置、用户身份或消息发送异常不阻塞工作项保存。
- 需求、问题、缺陷三类 `WorkItem` 使用同一套通知规则。

## 非目标

- 不新增站内通知中心或通知列表。
- 不为每条通知增加数据库投递记录和后台重试队列；本次沿用现有后台发送和日志记录方式。
- 不通知旧负责人、创建人或执行项负责人。
- 不改变工作项状态机、权限校验和更新接口的成功失败语义。

## 用户行为

### 负责人变更

- 负责人从 A 改为 B：只通知 B。
- 负责人从未指定改为 B：只通知 B。
- 负责人被清空：不发送负责人变更消息。
- 负责人未发生实际变化：不发送负责人变更消息。

### 状态变更

- 任意状态值从旧值变为新值时都通知当前负责人，并在消息中展示变更前后状态。
- 状态没有实际变化时不发送状态变更消息。
- 没有当前负责人时跳过状态通知。

### 同次更新合并

一次 `PATCH /work-items/:id` 同时修改负责人和状态时，先计算更新前后的差异，再按接收人合并变更内容：

- 新负责人是当前负责人时，发送一条同时包含负责人和状态变化的消息。
- 新负责人不是当前负责人时，给新负责人发送负责人变化消息，给更新后的负责人发送状态变化消息；两者相同则只发送一条。

### 一键查看

消息使用 Markdown 链接指向 Web 工作项详情：`/work-items/{workItemId}`。部署环境复用已有的 `FLOWX_WEB_BASE_URL` 配置站点公网根地址，例如 `https://flowx.example.com`。地址统一去除末尾 `/`，并对工作项 ID 做 URL 编码。

## 方案与组件

### 工作项更新服务

`WorkItemsService.update` 在更新前已读取完整工作项快照，保留更新前的 `ownerUserId`、负责人名称和 `status`。数据库更新成功后读取更新后的工作项，用快照差异生成通知输入。通知调用放入现有的后台任务模式，避免钉钉网络请求延长保存请求时间。

更新服务只负责：

1. 校验当前用户有权更新工作项。
2. 原子更新工作项并处理并发版本。
3. 计算负责人和状态变化。
4. 将变化交给通知服务。

### 钉钉通知服务

扩展 `DingTalkNotificationService`，新增工作项变更通知入口。入口接收：

- 工作项编号、标题、项目名称和工作项 ID。
- 变更人名称。
- 负责人变化的旧值、新值。
- 状态变化的旧值、新值。
- 组织的 `providerOrganizationId` 和目标 FlowX 用户 ID。

通知服务复用现有 `sendPersonalMarkdown`、`isEnabled`、钉钉身份解析和 Access Token 缓存。工作项状态通过统一的中文标签映射后写入消息，接口和数据库仍使用原始状态值。

### Web 公网地址

复用已有的 `FLOWX_WEB_BASE_URL` 配置和解析 helper。未配置时不拼接不可用的 localhost 链接；消息仍可发送文本内容，但记录 warning，提示需要配置公网地址才能使用一键查看。

## 消息格式

消息标题：`FlowX 工作项发生变更`

消息正文示例：

```markdown
## REQ-001 统一登录

- 项目：FlowX
- 变更人：产品甲
- 负责人：未指定 → 张三
- 状态：进行中 → 已完成

[查看工作项](https://flowx.example.com/work-items/work-item-1)
```

只有负责人变化或只有状态变化时，省略另一行。原始值为空时显示「未指定」；未知状态保留原始值，避免通知丢失信息。

## 失败与安全处理

- 工作项更新成功后，钉钉未配置、目标用户没有钉钉身份、Access Token 获取失败或消息发送失败，均只记录 warning，不回滚工作项更新。
- 通知只允许发送给当前组织内的负责人；更新服务已有负责人组织归属校验，通知入口再次要求组织和用户 ID 成对传入。
- 不在消息中输出 token、完整凭据或内部数据库信息。
- 公网地址仅用于生成链接，不参与权限判断；打开链接后仍由现有登录和组织隔离流程保护工作项详情。

## 测试策略

### API 单元测试

- 负责人从 A 改为 B 时发送给 B。
- 负责人清空时不发送负责人通知。
- 所有状态变化均发送，并包含中文旧状态和新状态。
- 同时修改负责人和状态时，相同接收人只调用一次发送入口。
- 无负责人、无钉钉配置、无身份和发送异常时更新仍成功。
- 消息包含可配置的公网链接；未配置时不生成错误 localhost 链接。
- 不同组织或非组织成员不能作为负责人，也不能成为通知接收人。

### 钉钉通知服务测试

- 复用现有身份解析和 Markdown 发送请求格式。
- 验证消息标题、中文状态、负责人变化和工作项链接。
- 验证 URL 末尾斜杠清理、工作项 ID 编码和缺少公网地址时的行为。

### 构建与文档

- 运行 API 测试和构建。
- 运行 Web 测试和构建，确保状态/负责人编辑流程未受影响。
- 更新 `.env.docker.example`、部署文档、用户手册和 Web 镜像。
- `FLOWX_WEB_BASE_URL` 同时供 API 通知链接和 Cursor 扩展使用，`flowx-local`、MCP、CLI、Skill 和 `@flowx-ai/protocol` 无需新增适配。
