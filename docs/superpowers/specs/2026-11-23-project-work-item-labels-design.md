# 项目工作项标签设计

状态：用户已于 2026-11-23 确认，源码实现与集成验证已完成；本文为本次功能的设计基线，验证记录见对应实施计划。

## 1. 目标与已确认决策

用户需要按项目维护自定义标签，并在新建、编辑工作项时选择。已确认：

- 标签属于项目，同一项目的所有版本共用，项目之间不共享。
- 一个工作项支持选择多个标签。
- 项目设置采用独立的“标签”页签（布局方案 A）。
- 标签支持预置颜色；创建时可选，提供默认色，不接受任意自定义色值。

下文补充了推荐的首版规则，需随本文一起审阅：所有有权操作项目工作项的组织成员均可维护标签；在项目设置统一创建；删除标签解除关联；列表支持展示和筛选。

## 2. 方案比较与推荐

| 方案 | 行为 | 收益 | 代价 |
| --- | --- | --- | --- |
| 项目标签库 + 工作项选择（推荐） | 在项目设置维护名称和颜色；新建、编辑时只选已有标签 | 规则集中，容易控制重复命名；各入口复用同一份标签 | 使用新标签需先进入项目设置 |
| 项目标签库 + 选择器即时创建 | 在上述基础上，允许在工作项选择器里直接创建标签 | 录入连续性更好 | 容易因拼写差异产生近似标签，增加嵌套写入与失败处理 |
| 每个工作项自由输入标签文本 | 工作项直接保存文本数组 | 最快录入 | 无法可靠地统一改名、改色和删除，不符合项目级维护目标 |

首版采用第一种方案。标签管理入口可从选择器跳转，后续若高频需要即时创建，再扩展同一个服务。

## 3. 标签规则

### 3.1 范围、命名与颜色

- 标签覆盖 `REQUIREMENT`、`ISSUE`、`BUG` 三类 `WorkItem`，不再各自建立标签库。
- 标签没有版本归属。工作项换版本、移出版本或关闭后保留标签。首版不新增工作项跨项目移动功能。
- 标签名称去除首尾空白，执行 Unicode NFC 规范化，长度为 1–30 个 Unicode 码点，拒绝换行与控制字符；保留内部空格。
- 同一项目内名称忽略英文大小写后唯一，存储规范化 `nameKey`，以数据库唯一约束兜底并发；不同项目可以使用同名标签。
- 预置色为 `GRAY`、`BLUE`、`CYAN`、`GREEN`、`AMBER`、`ORANGE`、`RED`、`PURPLE`，默认 `BLUE`。API 保存色名，Web 映射浅色/深色主题的边框、背景与文字。
- 颜色只是辅助识别，始终展示标签名称，不改变优先级、状态或工作流规则。
- 每个工作项最多选择 20 个标签；项目标签总量不设置产品上限，列表与选择器分页查询。
- 标签默认按 `createdAt ASC, id ASC` 稳定排序，首版不提供手动排序、分组、层级或合并。

### 3.2 修改与删除

- 编辑名称或颜色后，所有关联工作项下次读取均显示最新值；关联依赖标签 ID，改名不改变关联。
- 标签改名、改色不批量改写工作项 `updatedAt`，不重启工作流，不生成需求内容变更记录，也不触发负责人/状态通知。
- 删除操作使用确认对话框：`删除标签“前端”？该标签当前关联 12 个工作项。删除后将从这些工作项中移除，工作项会保留。`
- 确认后在事务中删除标签与关联，返回实际解除关联数量。标签删除不可通过页面恢复，重新创建同名标签得到新 ID，也不会重新关联原工作项。
- 删除后，已经打开的编辑器若仍提交该标签 ID，整次保存失败并保留草稿，提示刷新标签选项；不得静默丢弃无效标签后保存其他字段。
- 项目删除沿用项目生命周期；实际删除项目时，其标签与关联级联清理。工作项删除仅清理自身关联。

## 4. 页面与交互

### 4.1 项目设置：独立“标签”页签

现有 `ProjectDetailPage` 将简报/代码审查和版本设置直接铺在同一页。为落实方案 A，增加设置页内的页签：`版本`、`标签`、`简报`、`代码审查`，分别承载对应现有配置组件或新增标签组件。外层项目导航和标题保持现有样式。

- 使用 `/project-settings?projectId=…&tab=labels` 深链。默认 `tab=versions`；切换页签保留项目范围，标签搜索与分页使用独立参数。
- 保留 `/versions/manage` 的版本配置入口。旧 `#project-versions` 锚点映射到版本页签，避免既有链接失效。
- 标签页顶部显示“标签”和“新建标签”按钮，下面为搜索框与紧凑表格。
- 表格列：标签预览、工作项数量、操作（编辑、删除）。数量统计当前项目所有版本、所有状态、三类工作项，不仅统计当前版本。
- 首版使用数量只读，不提供跳转；避免将全项目三类工作项的使用总数链接到仅展示需求或单个版本的列表。
- 搜索按名称匹配，点击“查询”或回车生效；清除筛选立即生效；每页 20 条，沿用 `ListPagination`，不超过一页时隐藏分页器。
- 新建/编辑使用同一对话框：名称输入、8 色选择、实时标签预览。保存中禁用重复提交与关闭；校验或请求失败时保留输入。
- 空态显示“暂无标签”，附“新建标签”按钮；加载失败显示重试入口，不能伪装为空态。

### 4.2 工作项新建与编辑

- 在优先级/负责人附近增加“标签（可选）”；快速新建放在描述之后、备注之前。
- 选择器支持搜索、复选、多选后保持展开、选中计数、清空全部；外部点击或 `Esc` 关闭，使用键盘导航并可按空格切换复选项。
- 已选标签显示名称与颜色，并可逐个移除；长名称省略且可查看完整文本。折叠触发器最多显示两个标签及 `+N`，展开区域提供全部已选项。
- 选项每次有界加载，搜索只检索当前项目；已选项独立保存 ID 与摘要，不能因为分页切换或搜索结果中没有该项而丢失选择。
- 列表为空时显示“此项目暂无标签，可前往项目设置创建”。“管理标签”在新窗口打开标签页，当前工作项草稿保留；返回后支持“刷新标签”，已选值不被覆盖。无搜索结果时显示“没有匹配的标签”，不能混淆为项目未建标签。
- 选择标签仅修改草稿，与工作项其他字段一起保存。取消表单不产生标签关联；新建失败保留已选项。
- 手动切换创建项目时清空已选标签并提示“已切换项目，请重新选择标签”；切换同项目版本不清空标签。项目切换期间忽略旧请求，避免显示前一项目的选项。
- 首版不在选择器中直接新建或改名。

入口覆盖：版本工作台快速新建、`WorkItemEditDialog`、需求新建与编辑、统一工作项详情，以及缺陷新建/编辑和问题编辑。通过审查发现、测试结果等自动创建的工作项默认无标签，不自动继承来源项标签，后续可编辑。

### 4.3 列表展示、详情和筛选

- 在版本工作台三类 Tab，以及普通需求、问题、缺陷列表增加“标签”列；最多展示两个标签，超出显示 `+N`，悬停与键盘聚焦可查看全部；无标签显示 `—`。
- 详情页元信息区域完整展示标签，编辑表单使用同一个选择器。首次筛选不增加点击标签徽标直接过滤的隐式操作。
- 列表工具栏增加标签多选筛选，与其他筛选控件同高对齐，框下不额外显示匹配说明（2026-11-23 用户反馈修订）；选了“前端”“客户反馈”，命中其中任一个即可，与项目、版本、类型、状态、优先级等其他条件取交集。
- 遵循现有草稿查询机制，选择后点击“查询”或回车生效，提交筛选时回到第一页；清除筛选立即生效。
- URL 保存标签 ID 集合；切换同项目类型 Tab 或版本保留标签筛选，切换项目清空。
- 列表数据、总数及已有统计卡片均采用同一套过滤条件，不做客户端当前页过滤。若需要为统一列表补齐现有统计数据，应保持原有统计含义。
- 筛选标签被删除时显示“部分筛选标签已失效，请移除后重新查询”，不自动扩大查询范围。移除失效 ID 后重新查询。

## 5. 数据模型与服务边界

使用项目标签实体和显式多对多关联，避免在工作项上保存重复名称或 JSON 文本数组。

```text
Project 1 ── N ProjectLabel
WorkItem 1 ── N WorkItemLabel N ── 1 ProjectLabel

ProjectLabel
  id, projectId, name, nameKey, color, createdAt, updatedAt
  UNIQUE(projectId, nameKey)
  INDEX(projectId, createdAt, id)

WorkItemLabel
  workItemId, labelId
  PRIMARY KEY(workItemId, labelId)
  INDEX(labelId, workItemId)
```

- `WorkItem` 与 `Project` 增加关系字段。标签删除和工作项删除的关联均采用级联清理。
- `ProjectLabelsService` 放在 `projects` 模块，负责名称规范化、项目校验、标签 CRUD、使用数量与标签归属校验；工作项读写服务复用该服务。
- 标签关联写入与工作项创建/更新在同一事务中；更新沿用 `updatedAt` 乐观并发控制，必须先核对版本，再替换关联。旧客户端未带 `updatedAt` 时继续沿用既有行为。
- 标签 ID 必须全部存在且属于工作项项目。事务内重新核对归属与存在性，以唯一约束、外键处理并发创建、删除竞争；整次写入成功或回滚。
- 标签自身编辑沿用可选 `updatedAt` 并发校验；Web 编辑时传入，冲突保留草稿并要求刷新。删除视为显式操作，确认后删除当前标签，响应给出实际使用数量。
- 跨项目标签关联无法仅靠简单外键保证，由集中服务严格校验；新增标签和关联模型同时注册 `organization-scope.ts` 的组织隔离规则，禁止依赖登录 guard 代替资源归属校验。
- 读取端统一将关联投影为 `labels: [{ id, name, color }]`；标签管理列表额外包含 `workItemCount`，不暴露中间表结构。
- 列表使用批量关联查询，避免每个工作项单独查询标签或使用数量。
- 迁移仅新增表、索引和关系；已有工作项自然返回空标签数组，无需回填业务数据。SQLite 升级脚本需检查是否需要接入现有 Docker migration 执行链。

## 6. API 契约

以下路径省略统一的 `/api` 前缀，均为拟增加/扩展能力。

| 接口 | 请求 | 响应 |
| --- | --- | --- |
| `GET /projects/:projectId/labels` | `page/pageSize/q`，标准分页，最大 100 | `PageResult<ProjectLabel>`，含 `workItemCount` |
| `POST /projects/:projectId/labels` | `{ name, color? }` | 新标签，含 `id/projectId/name/color/updatedAt` |
| `PATCH /projects/:projectId/labels/:labelId` | `{ name?, color?, updatedAt? }`，至少一个业务字段 | 更新后的标签 |
| `DELETE /projects/:projectId/labels/:labelId` | 无请求体 | `{ ok: true, removedAssociations }` |
| 已有工作项创建接口 | 新增可选 `labelIds: string[]` | 新增 `labels` 摘要数组 |
| `PATCH /work-items/:id` | 新增可选 `labelIds: string[]` | 新增 `labels` 摘要数组 |
| 工作项列表与详情 | 列表新增 `labelIds` 查询参数 | 保持既有分页格式，工作项新增 `labels` |

字段语义：

- 创建时省略 `labelIds` 或传 `[]` 均表示无标签；更新时省略表示保留，`[]` 表示清空，非空数组表示整体替换；显式 `null`、空 ID 或非数组均返回 400。
- 重复 ID 去重后最多 20 个；共享 schema 明确检查数组与 ID 类型，不能被 `@IsOptional()` 意外放过 `null`。
- HTTP 查询用逗号分隔的 `labelIds`（ID 不含逗号）；MCP 接收数组并明确序列化为该格式。最多 20 个，空参数等同无筛选。标签之间固定 OR，不新增匹配模式参数。
- 工作项返回的标签使用稳定排序，读取无需再拉取项目全量标签。
- `GET /work-items`、`GET /projects/:projectId/versions/:versionId/work-items` 以及现有 `/bugs` 列表、详情和创建/编辑链路必须同步；不得只修改通用工作项接口而漏掉缺陷页面。
- 仍在使用的原型 ZIP 创建入口应在同一创建事务中支持选定标签；先创建再补标签会产生部分成功，不作为正式实现。

权限与错误：

- 沿用当前项目能力，已登录且属于项目所在组织的成员可查看、创建、编辑和删除标签，可给有权编辑的工作项绑定标签；不新建“项目管理员”权限体系。
- 无登录返回 401；没有组织上下文按现有组织保护拒绝；资源不存在、其他项目标签或无权访问的资源统一返回不泄露他项名称的 404。
- 空名、超长名称、不支持的颜色、超过标签数量等返回 400；同项目重名或 `updatedAt` 冲突返回 409。
- 已删除/不属于项目的标签作为无效标签返回 404，提示“部分标签不存在或不属于当前项目，请刷新标签后重试”；返回机器可识别错误码 `PROJECT_LABEL_UNAVAILABLE`。
- 重名、并发冲突使用 `PROJECT_LABEL_NAME_CONFLICT`、`RESOURCE_UPDATED`；沿用既有异常响应外壳增加稳定 `code`，不把数据层异常直接暴露给用户。

## 7. Web、API 与本地工具影响

本地适配结论：**需要适配**。标签是工作项业务字段，本地 Agent 需要能发现项目可用标签，并正确绑定、读取与筛选；不能判定为只涉及 Web 视觉。

| 消费者 | 拟改动与依据 |
| --- | --- |
| Web | 新增 `ProjectLabelsPanel`、`ProjectLabelDialog`、`ProjectLabelSelect`、`ProjectLabelBadges`；使用现有 Tabs、Dialog、Popover/复选项、分页、toast 和设计令牌；`api.ts`、各类工作项类型和请求 payload 同步 |
| API | 项目标签 CRUD 与集中校验服务、工作项原子关联写入、列表筛选、`/bugs` 消费路径、原型导入创建路径、组织隔离注册和 additive migration |
| `@flowx-ai/protocol` | 定义标签颜色枚举、标签摘要和输入 schema；`WorkItemRef` 增加可选 `labels` 兼容字段，具体新版工作项 API 始终返回数组；Web/API/MCP 复用契约，不让 schema 与常量分叉 |
| MCP | 新增只读 `flowx_list_project_labels(projectId, page?, pageSize?, q?)`；扩展 `flowx_create_work_item`、`flowx_update_work_item` 的 `labelIds` 输入及实际请求体；扩展 `flowx_list_version_work_items` 的标签筛选与返回 |
| 本地上下文 | 检查 `flowx_get_task_context` 与工作流阶段交接上下文对 `WorkItem` 的裁剪，增加标签摘要供读取；标签属于参考元信息，不能作为执行指令、自动变更状态或确认门禁 |
| CLI / loopback / Adapter | 复用同一 MCP/API 客户端，不单独引入标签 CLI 命令；核查所有工作项 DTO 裁剪与上下文映射，防止新字段被丢弃；执行项领取、回传协议不因标签改变 |
| Skill 模板与文档 | 新建/编辑工作项说明补充“先查询目标项目标签，再传 ID；未指定标签则保留缺省语义；不自行创建/猜测标签”；沿用已有去向规则，不因为标签重新选择已绑定项目 |

首版标签创建、改名、改色和删除面向 Web 管理，暂不新增 MCP 标签管理写工具。本地 Agent 可查询已有标签并在工作项上选择/清空；若需新增标签，说明应由用户进入项目设置维护。这一限制需写入工具描述与本地手册。

兼容策略：

- 旧客户端不带新字段时保持原行为，更新工作项其他字段不会清空标签；旧读取客户端可以忽略新增响应字段。
- 新客户端连接旧服务端：首次使用标签时查询当前项目的标签列表；仅在错误响应明确表明该路由不存在（例如 Nest 的 `Cannot GET /api/projects/…/labels`）时判定能力缺失。未要求标签的旧操作可继续，用户明确要求标签时返回可识别“不支持，请升级服务端”，不删除参数后伪报成功。401/403、资源 404、网络故障不得误判为能力缺失。
- `forbidNonWhitelisted` 会让旧服务端拒绝未知写入字段；保留该行为，不为兼容放松校验。新 MCP 在明确指定标签时检查响应字段，避免返回不支持时仍声称已设置。
- 新能力作为可选扩展，不改变执行协议语义或强制提升 `FLOWX_PROTOCOL_VERSION`；本地包按现有发布机制升级。说明 `flowx-local update` 与 IDE MCP 重新加载步骤。
- 标签是即时元信息：改名、改色、解除关联不回写已冻结 Artifact、历史测试快照和审查产物；新获取的工作项上下文显示当前标签。

## 8. 异常、并发与可访问性

- 两人并发创建同名标签只允许一条成功，失败者得到可操作的重名提示；不能产生重复数据。
- 工作项标签整体替换与其他字段更新共用事务和工作项并发基线；失败不能留下半套关联或已修改的其他字段。
- 标签删除和绑定竞争时，成功绑定发生在删除前则随后被正常解除；删除先完成则绑定失败，不产生悬挂关联。事务内校验与外键共同保证。
- 请求失败保留工作项草稿、原标签和当前列表上下文；加载失败不把已选项改成空数组。
- 删除当前筛选标签或当前编辑标签后按“失效”状态提示，显式移除后再提交，不静默扩大筛选或覆盖草稿。
- 预置颜色在浅色、深色模式均需有可读对比；色块带中文可访问名称和选中标识；复选选择器包含键盘与读屏状态。
- 名称按纯文本渲染，省略展示不改变实际值；保持现有紧凑表格、固定操作列和对话框中间滚动区域。

## 9. 验收与验证范围

功能验收：

1. 项目 A 创建“前端”标签，项目 B 不可见；B 可独立创建同名标签。
2. 同项目三类工作项均可选择多个标签、保存、回显和移除；不选标签也可创建。
3. 工作项更换同项目版本或移出版本后保留标签；切换创建项目后清空标签选择。
4. 标签改名、改色后关联工作项下次读取展示最新值；不触发工作流或负责人通知。
5. 删除已使用标签前显示使用数量，确认后工作项保留；过期编辑器提交旧标签必须失败且保留草稿。
6. 列表按任一所选标签筛选，并与其他条件取交集；总数、分页及现有统计一致，URL 可恢复条件。
7. 新建、编辑、标签搜索分页、无标签、无匹配、网络失败和无权限状态清楚且可重试。
8. 本地真实 MCP 工具可发现并查询标签，创建、更新与版本查询可透传标签；旧请求修改其他字段保留已有标签。

实现时先补高风险边界测试：

- 数据与 API：名称规范化、大小写重复、颜色与空值校验、项目/组织越权、跨项目绑定、事务回滚、并发重名、删除/绑定竞争、乐观并发冲突和旧客户端省略字段。
- 页面：设置页签深链、管理对话框、多选搜索分页保留、项目切换、表单取消/失败、标签列折叠、OR 筛选、类型/版本切换、失效标签和 `/bugs` 路径。
- 本地：工具发现与 schema、真实 MCP → HTTP 路径/字段/空数组 → API 契约、响应可消费性、未授权与能力不足、工作项上下文标签裁剪。
- 回归：执行项领取/回传与状态推进不受标签操作影响；原型 ZIP 与缺陷专属字段保持现有能力。

实现完成应运行 `pnpm prisma:generate`、API/Web/local/protocol 对应 test 与必要 build、根目录 `pnpm check`，并进行浏览器浅色/深色及键盘检查。本轮仅设计文档和原型，验证文档差异与原型交互，不以此宣称功能实现。
