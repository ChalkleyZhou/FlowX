# 版本工作台工作项编辑弹框设计

## 背景

版本工作台当前按需求、问题、缺陷展示同一版本下的工作项，但“详情”操作会跳转到统一工作项详情页。统一详情页的返回按钮固定回到版本工作项，无法准确还原用户从需求列表、问题列表或缺陷列表进入的来源。版本会议场景下，用户需要频繁查看和修改工作项，跨页面跳转会丢失当前版本、类型 Tab、搜索和分页上下文。

## 目标

- 版本工作台三个类型 Tab 的工作项操作均在当前页面打开编辑弹框。
- 弹框保持云效式的快速编辑体验，保存后仍停留在当前版本、Tab、搜索和分页位置。
- 弹框仅编辑常用字段：标题、描述、优先级、版本、备注。
- 编号、类型和状态在弹框中展示；状态只读，状态调整继续使用统一详情或工作流入口。
- 从普通需求、问题、缺陷列表进入统一详情时，详情页根据来源返回；直接打开详情链接时回到统一工作项列表。

## 非目标

- 不在弹框中编辑状态、负责人、执行计划、工作流、排期、类型专属字段或质量关联。
- 不改变真实 UUID 的 API、路由和数据关联用途。
- 不新增后端接口；复用现有 `updateWorkItem` API。
- 不把统一详情页完整嵌入弹框。

## 交互设计

### 版本工作台

`VersionWorkItemsPage` 为当前选中 Tab 的操作列打开 `WorkItemEditDialog`，不再使用详情链接。弹框标题根据类型显示“编辑需求”“编辑问题”或“编辑缺陷”，同时显示可读编号和只读状态。表单字段为：

- 标题（必填）
- 描述
- 优先级
- 版本
- 备注

打开弹框时以当前列表对象填充草稿。保存时发送当前工作项 ID、编辑字段和 `updatedAt`，成功后用接口返回对象替换当前列表中的对应记录并关闭弹框；失败保留草稿并展示错误。关闭或取消不修改列表。保存版本时，如果工作项离开当前版本，保存后从当前列表移除并刷新总数。

问题和缺陷使用同一表单与 API，只根据类型显示标题和编号；类型专属字段保持只读或在统一详情中维护。

### 统一详情返回来源

普通需求、问题、缺陷列表生成详情链接时，通过 React Router location state 传递当前列表路径和查询参数。`WorkItemDetailPage` 优先使用该返回地址；没有来源状态时回退到 `/work-items`。返回操作不再根据工作项是否有版本固定跳转版本工作台。

来源状态只用于页面导航，不进入 API 请求或持久化数据。刷新或直接访问深链时使用统一工作项列表回退，避免使用不可信的任意外部 URL。

## 组件与数据流

- 新增 `apps/web/src/components/WorkItemEditDialog.tsx`，负责草稿初始化、字段校验、保存状态和错误提示。
- `VersionWorkItemsPage` 持有当前编辑对象和弹框开关；按当前 Tab 的数组更新保存结果。
- `RequirementListTable`、问题列表和缺陷列表将详情链接的来源路径传入 `Link state`。
- `WorkItemDetailPage` 读取 `useLocation` 的来源状态并生成返回链接。
- `api.updateWorkItem` 和现有 `WorkItem` 类型继续作为唯一 API 和数据契约。

## 错误与边界

- 标题为空时禁止提交并在字段附近提示。
- 保存期间禁用表单和关闭操作，避免重复提交。
- API 返回冲突或失败时保留输入，允许用户重试。
- 当前对象已被其他操作更新时，沿用 `updatedAt` 乐观并发校验，错误由现有 API 消息展示。
- 保存后版本变更导致对象不再属于当前版本时，从列表移除并重新读取当前页，避免展示过期记录。

## 验证

- 组件测试覆盖三个类型打开弹框、草稿回填、成功保存、失败保留输入和取消关闭。
- 版本工作台测试覆盖保存后当前 Tab 列表更新，以及跨版本保存后的列表刷新。
- 详情页测试覆盖从普通列表返回原路径、来源缺失时回退 `/work-items`。
- 运行 `pnpm --filter flowx-web test` 和 `pnpm --filter flowx-web build`。

## 本地工具适配结论

本次为 Web 页面交互和导航状态调整，不改变需求、工作项、阶段状态、执行控制、Artifact/Evidence 或 API 契约；`flowx-local`、MCP、CLI、Skill、Adapter 和 `@flowx-ai/protocol` 无需适配。
