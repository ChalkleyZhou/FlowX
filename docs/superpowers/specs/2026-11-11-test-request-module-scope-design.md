# 提测范围模块批量确认设计

## 背景

当前提测范围工作台已经收敛为目录筛选、单列表勾选和按需查看详情，但主要操作仍然是逐条切换用例。版本用例数量较大时，测试人员需要重复执行大量低价值点击，无法在进入页面后快速判断每个模块是否覆盖、哪些项目真正需要人工决策。

本次设计以“模块批量确认”为主流程。AI 先根据需求、代码变更和已有用例生成推荐范围；人工按模块确认默认结果，只处理模块内少量例外，然后进入执行人分派。

## 目标

1. 进入提测范围后，先看到版本级范围总览和模块级覆盖情况。
2. 模块默认沿用 AI 推荐结果，支持一次恢复该模块的 AI 推荐或移除该模块全部已纳入用例。
3. 默认只展示需要人工判断的例外，用户可以在模块内展开全部用例并查看详情。
4. 批量操作继续使用 `scopeRevision` 做并发保护，保存失败可重试且不丢失用户当前视图。
5. 范围确认后沿用现有分派、执行轮次、报告和本地 Agent 链路。

## 非目标

- 不改变测试范围确认后的快照语义、人员分派规则或执行结果模型。
- 不自动把 AI 新用例保存到长期用例库；仍由人工在详情中触发保存。
- 不把模块批量操作扩展为可编程规则引擎；本轮只提供 AI 推荐恢复和整模块移除。
- 不新增 FlowX MCP、CLI、Skill 或 `@flowx-ai/protocol` 工具。
- 不在模块列表中常驻展示步骤、预期结果等长文本。

## 用户流程

### 1. 进入范围工作台

范围页顶部显示当前项目、版本和提测标题。工作台首屏展示四项摘要：

- `预计提测`：当前纳入范围的用例数。
- `AI 推荐`：AI 默认推荐纳入的用例数。
- `待处理例外`：需要人工确认的用例数。
- `覆盖变更点`：已被纳入用例覆盖的需求或变更点比例；没有可计算覆盖率时显示“暂无数据”。

AI 仍在生成时，摘要区域显示进度状态，模块批量操作和范围确认按钮禁用。首屏已有数据时后台轮询只更新状态和数据，不清空当前内容。

### 2. 按模块查看状态

左侧保留按需加载的“用例库 → 模块”树。树节点只负责定位模块，不直接改变范围。每个模块节点或模块卡片显示：

- 当前纳入数 / 当前模块可用用例总数；
- AI 推荐数；
- 例外数；
- 状态：`全部纳入`、`部分纳入`、`未纳入`。

AI 新用例没有正式模块时进入“AI 新用例”虚拟分组，仍可单独查看和处理。

进入模块后，主面板显示模块摘要和两个批量动作：

- **纳入 AI 推荐**：恢复该模块中原本由 AI 推荐的候选。它只恢复候选，不把未被 AI 推荐的库内用例全部加入；已经人工移除的 AI 候选会恢复为纳入状态。
- **移除全部**：移除该模块当前已纳入的所有候选，包括 AI 推荐和人工补选。动作前显示模块名称和影响条数，要求一次明确确认；成功后提供轻量“已移除，可撤销”提示。

两个动作都显示执行中的数量和保存状态，连续点击串行排队。批量保存完成后，模块摘要、顶部总览和例外数量一起刷新。

### 3. 只审阅例外

模块默认打开“只显示例外”。例外由服务端依据候选的 `action`、`resolution`、`matchReason`、`decisionNote` 和覆盖关系计算，并返回例外原因。已经通过人工操作写入明确 `decisionNote` 的移除或补选不再重复计入待处理例外。例外包括：

- 尚未作出人工决定、且 AI 与历史用例或覆盖关系存在冲突的候选；
- AI 新生成且尚未完成审阅的用例；
- 未被 AI 推荐、但用户通过“全部用例”视图补选后需要确认来源的候选。

例外行显示标题、优先级、模块路径、来源和简短原因。点击行打开现有详情抽屉，展示前置条件、测试数据、步骤、预期结果、覆盖关系和来源；详情不改变范围。AI 新用例继续显示“保存到用例库”入口。

用户可以切换“只显示例外 / 全部用例”，也可以使用标题搜索。切换视图、目录和页码只改变查询，不修改范围选择。

### 4. 确认并进入分派

底部固定操作栏显示“已确认 X 条”和“还有 Y 个例外待查看”。存在待处理例外时，主按钮仍可点击，但按钮旁明确提示数量；点击后弹出确认摘要，列出各模块纳入数和剩余例外。用户确认后调用现有 `prepareTestRequest`，成功进入按模块分派执行人；失败保留工作台状态并显示真实错误。

已生成测试计划快照、提测已开始或流程已结束时，范围工作台转为只读；目录、搜索和详情仍可用，批量操作和确认按钮禁用。

## 数据与 API

### 模块摘要

在现有 `GET /quality/case-libraries/:libraryId/modules` 上增加可选的 `testRequestId` 查询参数。传入该参数时，服务端按当前提测的 `workspaceId`、`projectId` 和共享/项目用例库权限过滤，并为返回的每个模块附加范围摘要；不传时保持原用例库管理接口行为。摘要返回：

```ts
interface TestRequestScopeModuleSummary {
  moduleId: string;
  libraryId: string;
  moduleName: string;
  totalCount: number;
  includedCount: number;
  aiRecommendedCount: number;
  exceptionCount: number;
  status: 'ALL' | 'PARTIAL' | 'NONE';
}
```

服务端按模块及其后代模块汇总，不能依赖当前列表页的 20 条数据。没有正式模块的 AI 新用例归入固定的虚拟分组，不写入 `TestCaseModule`。

范围草稿查询增加 `view=exceptions`。该视图沿用 `libraryId`、`moduleId`、`q` 和分页参数，只返回当前模块需要人工判断的候选，并为每条记录附加 `exceptionReason`；现有 `view=selected|library` 的含义和返回字段保持不变。

### 模块批量动作

继续使用 `PATCH /quality/test-requests/:id/scope-draft/module` 和 `scopeRevision` CAS。为保持旧客户端兼容，在现有 `included` 字段旁增加可选策略字段：

```ts
type ScopeModuleStrategy = 'AI_RECOMMENDED' | 'ALL';

interface UpdateTestRequestScopeModuleInput {
  scopeRevision: number;
  moduleId: string;
  included: boolean;
  strategy?: ScopeModuleStrategy;
}
```

- 新 Web 工作台的“纳入 AI 推荐”发送 `included: true, strategy: 'AI_RECOMMENDED'`。
- 旧客户端发送 `included: true` 时继续保持原有“整模块纳入”语义，按 `strategy: 'ALL'` 处理。
- “移除全部”发送 `included: false`，忽略策略字段。

`AI_RECOMMENDED` 只恢复 `action !== 'EXCLUDE'` 的候选，并把被人工移除的候选恢复为 `ACCEPTED`；不创建没有 AI 候选的库内用例。模块操作仍覆盖完整后代模块和分页外用例，已确认快照继续拒绝修改。

`TestCaseModule` 的 Web 类型增加可选 `scopeSummary`，`TestDesignCandidate` 增加可选 `exceptionReason`。旧查询和旧返回字段保持可用；新增字段采用可选形式，便于服务端和 Web 分开升级。

## 前端组件边界

- `QualityScopeDraftPanel`：负责工作台状态、串行写入、轮询、确认和总览摘要。
- `QualityScopeDirectory`：负责按需加载目录和选择当前模块；消费模块摘要但不直接写入范围。
- 新增或拆分 `QualityScopeModuleOverview`：渲染模块卡片、纳入状态、批量动作和批量确认提示。
- `QualityScopeCaseDetails`：继续负责详情抽屉和 AI 新用例入库，不复制范围写入逻辑。
- `apps/web/src/api.ts`、`apps/web/src/types.ts` 与 API DTO 同步新增摘要和策略字段。

所有异步刷新区分首屏加载和静默刷新；后台轮询、模块批量写入和详情保存不会清空已展示内容。写入失败时保留当前模块、筛选、详情和待处理状态，提供“重新同步”；过期响应不得覆盖新范围。

## 错误与边界

- `scopeRevision` 冲突：停止后续写入，提示“范围已被其他操作更新”，提供重新同步；不自动覆盖用户选择。
- 网络失败：显示模块级或页面级错误，保留已加载内容和当前筛选，不提示虚假的保存成功。
- 模块没有可用用例：显示空状态，批量按钮禁用；不创建空快照。
- 已确认快照或提测已开始：所有写入接口由服务端拒绝，前端切换只读并保留查看能力。
- “移除全部”取消：不发请求，不改变 `scopeRevision`。
- AI 生成失败：保留错误原因；无法确认范围时引导回测试设计页重新分析。

## 验证

### API

- 模块摘要按项目/共享库隔离，覆盖模块后代、空模块和分页外用例。
- `AI_RECOMMENDED` 只恢复 AI 候选；旧 `included: true` 客户端继续整模块纳入。
- `REMOVE_ALL`、重复请求、过期 `scopeRevision`、确认快照后修改和越权访问均有测试。
- 事务失败时不产生部分模块更新，返回真实冲突或权限错误。

### Web

- 顶部总览和模块卡片展示正确的纳入数、AI 推荐数、例外数与状态。
- “纳入 AI 推荐”不加入未推荐库内用例；“移除全部”确认、成功提示、撤销和失败恢复正确。
- 只显示例外、全部用例、搜索、目录切换和详情抽屉不丢失范围状态。
- 连续批量操作按最新 `scopeRevision` 顺序保存；旧查询回包不覆盖新状态。
- 生成中、网络失败、权限错误、已确认只读、空模块和无例外状态均有覆盖。
- 运行 `pnpm --filter flowx-api test`、`pnpm --filter flowx-web test --run`、两端 build、`pnpm check`、`git diff --check` 及用户手册镜像校验。

## 本地工具适配结论

**复用现有能力，不需要适配。** 本次变化只发生在 Web 提测范围草稿浏览和 API 的模块摘要/批量策略兼容层。`flowx-local`、MCP、CLI 和 `@flowx-ai/protocol` 继续读取确认后的测试计划、快照、领取、回传和报告接口，不消费 Web 草稿状态，也不新增本地工具。交付说明需明确 API 新字段向后兼容，旧本地客户端行为不受影响。
