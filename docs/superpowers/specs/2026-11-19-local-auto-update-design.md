# flowx-local 调用触发自动更新

## 已确认目标

CLI 启动、MCP 工具调用和 loopback 请求触发检查，共享五分钟缓存；本次操作不等待联网或安装。新版在独立目录安装、校验，成功后原子切换入口。已运行的 MCP 保留原版本，重新连接时生效；后台服务通过文件事件感知新版就绪，处理完全部请求及业务后通过稳定父进程重新启动；空闲时直接切换。没有定时版本轮询。

## 启动与安装边界

`dist/index.js` 是稳定入口，按原始安装位置分隔更新仓库，避免源码、npm 和 pnpm 安装串用。每个更新仓库位于 `~/.flowx/updates/<安装路径摘要>`，保存缓存、进程锁、版本目录与活动版本指针。入口只选择版本不低于原始包的有效安装；指针损坏或新版导入失败时使用原始包。源码开发默认关闭自动检查。

后台 worker 用当前 Node 对应的 npm CLI 安装 npm 官方源 `latest` 指向的稳定版本，不修改当前包目录，不执行安装脚本，不调用 sudo。安装和启动校验均有超时。锁覆盖检查、安装与发布，存活的锁持有者不能被其他进程抢占；锁采用每次申请唯一文件的 bakery 算法：先原子发布选号标记、再选票，出票后重新枚举竞争者；不删除共享路径来抢锁。死 PID 记录不参与竞争，活进程的选号或损坏记录保守返回忙碌，票号溢出时放弃。若多个申请同时退让，下次活动可重试；若死进程 PID 被长寿进程复用，需等其退出。检查失败也缓存五分钟，避免离线请求风暴。MCP stdout 只承载协议，后台输出写入更新日志。

## 生效和配置

`autoUpdate: false` 或 `FLOWX_LOCAL_AUTO_UPDATE=0` 关闭自动检查；手动 `flowx-local update` 可立即执行同一升级流程。后台刷新已安装且仍与旧模板一致的 FlowX Skill，自定义内容保留并记录；只修改已有 FlowX MCP 配置，不创建未安装的 IDE 配置。稳定入口使 MCP 配置与系统服务无需每个版本改路径。新 MCP 工具发现发生在重新连接之后。

`status` 返回当前 CLI、后台服务实际运行版本、已准备版本、最近检查时间与结果；错误状态仅保存简短分类，不保存可能含凭据的子进程输出。详细安装输出仅为 npm 官方源操作日志，不包含 FlowX token。

## 本地适配

结论：**需要适配**。影响 CLI、stdio MCP、loopback daemon、Skill 刷新及 IDE 启动路径。API、Web 和 `@flowx-ai/protocol` 业务契约复用现有能力；不新增 MCP 业务工具，不改变权限、领取或回传语义。设计完成后已发布为 `@flowx-ai/local@0.8.0`；已有 0.7.2 客户端需要手动运行一次更新。Windows、macOS、Linux 的核心调度使用 Node API，实机未验证的平台在交付时注明。

## 验收

覆盖缓存、并发和遗留锁、关闭开关、离线、安装失败、校验失败、版本倒退、原子入口、源码隔离、自定义 Skill 保留、真实 CLI 启动与 MCP 调用触发、服务请求排空和信号转发。执行 local 测试与构建、`pnpm check`、diff 检查与两份手册镜像校验。
