# 原型重新导入与换包设计

用户已确认：失败时统一为「重新导入」，AI 和 ZIP 均可调整；换包完整替换分析材料，旧包可追溯。已进入研发的需求通过「需求变更 → 重新走流程」上传新包，保留旧流程和产物。

## 失败重新导入

- 同一表单展示当前 AI、当前 ZIP 和可选新 ZIP，只有一个「重新导入」主按钮。
- 未选新包时沿用原材料；选择后显示文件名，可移除选择恢复原包；非法或超限文件阻止提交。
- 新包只分析自身文件，不继承旧文件、分析和答案；历史原始包继续可下载。并发与旧 revision 仍由 CAS 拒绝。
- 文件读取失败保留原材料和可继续重试的状态，界面刷新到最新 revision，并保留未提交的选择。

## 已成功需求的原型变更

- 需求变更表单可选 ZIP；选包后只能「重新走流程」，说明可留空并使用文件名生成简短说明；AI 默认沿用原流程或原型配置，可改。
- 新材料独立保存到变更名下，通过可空 JSON 字段保存文件摘要、清单、AI 及分析快照。幂等键和文件哈希一起校验，不新增需求。
- 提交后后台分析；STARTING 状态显示进度，失败保留材料并通过「继续启动流程」重试。分析成功后复用快照，不重复消费 AI；活跃任务冲突沿用现有待启动机制。
- 新流程从该变更的不可变原型快照接续技术方案，旧导入记录、旧工作流和产物均保留。正式变更上下文纳入新分析，后续研发可读取。
- ZIP 下载沿用组织权限、包大小和安全解压限制。异常不泄露上游凭据或原型正文。

## 验证

覆盖整体替换与历史下载、无新包重试、移除/非法文件、失败保留选择与 revision 恢复；覆盖变更上传的组织隔离、幂等、后台失败重试、新流程快照、AI 传递及旧流程不被覆盖。执行受影响测试、全仓检查和本地页面交互验证，更新手册及镜像。
