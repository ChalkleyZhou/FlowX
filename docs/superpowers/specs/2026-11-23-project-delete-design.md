# 项目永久删除设计

## 目标

为 FlowX 增加项目永久删除能力。删除操作只能由当前组织的主管理员（`organization.role === 'admin'`）执行；删除会永久清理项目及其业务关联数据。

## 已确认规则

- 删除方式：永久删除，不提供项目归档替代。
- 权限：仅 `admin` 可以删除；`sub_admin` 和 `member` 均返回无权限错误。
- 执行保护：项目存在执行中的工作流阶段或活动本地执行会话时拒绝删除，返回 `409`，不修改任何数据。
- 已完成、失败、取消或无活动执行会话的项目允许删除。
- 删除是不可恢复操作，前端必须二次确认并要求输入项目名称。

## API 设计

新增 `DELETE /projects/:id`。

Controller 从 `req.authSession.organization.role` 读取当前组织角色；角色不是 `admin` 时抛出 `403`。Service 使用组织作用域查询项目，避免跨组织访问；项目不存在时返回 `404`。

删除 Service 在一个 Prisma transaction 中执行：

1. 查询项目及项目下工作项、工作流和执行会话的活动状态。
2. 如果存在 `StageExecution.status === 'RUNNING'` 或 `ExecutionSession.status` 属于 `ACTIVE_EXECUTION_SESSION_STATUSES`，抛出 `409`，事务不产生写入。
3. 将 `Project.currentVersionId` 置空，解除当前版本的 `Restrict` 外键。
4. 清理项目直接关联且不是级联删除的记录，包括简报/每日代码审查及其投递日志、项目缺陷关联、测试设计和提测中的版本引用、交付目标投递日志等；需要解除的跨项目引用设置为 `null`，项目历史记录随项目清理。
5. 删除 `Project`。依赖已配置 `onDelete: Cascade` 的工作项、工作流、执行计划、标签、版本、配置和测试子记录由数据库级联清理。
6. 返回 `{ success: true, projectId }`。

所有清理操作必须使用项目 ID 条件，并复用现有组织作用域；事务任一步骤失败时整体回滚。

## Web 交互

- `ProjectsPage` 项目卡片的操作区仅对当前会话 `organization.role === 'admin'` 显示“删除项目”。
- `ProjectDetailPage` 页面标题操作区同样显示入口，避免管理员必须返回项目池。
- 确认弹窗展示项目名称、需求/工作项数量和不可恢复提示；输入框必须完全匹配项目名称后才能提交。
- 删除中禁用弹窗操作并显示“删除中…”。成功后关闭弹窗、刷新项目列表；如果删除的是当前项目，清除项目作用域并跳转到 `/projects`。
- `403`、`404`、`409` 和网络错误均在弹窗中展示服务端返回的可读错误，不清空用户输入以便重试。
- 非 `admin` 用户不展示入口；API 仍是最终权限边界。

## 错误语义

- `403`：`只有主组织管理员可以删除项目。`
- `404`：`项目不存在。`
- `409`：`项目存在执行中的工作流或本地任务，请先完成或取消后再删除。`
- 成功响应不返回已删除数据，避免前端继续使用失效对象。

## 测试范围

后端新增项目删除集成测试，覆盖：

- `admin` 删除成功并清理项目、版本、工作项、工作流、标签、简报/代码审查及测试关联；同组织其他项目保留。
- `member`、`sub_admin` 被拒绝；跨组织项目返回 `404` 或组织作用域拒绝。
- 活动工作流阶段和活动本地会话分别阻止删除，数据库无变化。
- 不存在项目返回 `404`；事务中途失败时数据完整回滚。

前端新增 API helper、权限入口和确认弹窗测试，覆盖名称匹配、成功跳转、错误展示和非管理员隐藏入口。

## 本地适配结论

本次能力仅面向 Web 管理台的组织主管理员，不增加 FlowX MCP、CLI、Skill 或 `@flowx-ai/protocol` 写工具。删除涉及权限和不可逆业务数据清理，Local Agent 不应拥有该入口；现有本地工作项和执行链路在删除保护触发时继续收到 `409`，无需新增协议字段。
