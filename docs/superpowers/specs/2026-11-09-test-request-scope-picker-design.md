# 提测范围树状穿梭框设计

## 状态

已确认，进入实现。

## 目标

把提测范围确认收敛成用例库常见的双栏树状穿梭框，让测试人员直接从用例库树中调整本次范围。列表只展示用例标题和层级信息，不展开步骤、预期结果、匹配理由等测试用例详情。

## 交互方案

### 左侧：可选用例库

- 展示当前 Workspace 共享库和当前项目库。
- 用例库下展示模块树，模块下展示用例。
- 支持按名称搜索，支持展开/收起。
- 节点可选粒度为用例库、模块和单条用例；选择父节点时包含其下可见子节点。
- 用例节点只展示标题和必要的优先级标记。

### 右侧：本次提测范围

- 与左侧保持相同的库 → 模块 → 用例层级。
- AI 推荐的 `REUSE`、`OPTIMIZE`、`CREATE` 默认出现在右侧。
- `CREATE` 用例显示“AI 新用例”标记；保存到长期用例库仍需通过节点操作人工触发。
- 支持搜索、展开/收起、按库/模块/单条用例移除。
- 不在列表展示步骤、预期结果、测试数据、匹配理由或完整 AI 分析内容。

### 中间和顶部操作

- 中间只保留“加入范围”和“移出范围”两个动作。
- 顶部只展示 `AI 推荐`、`当前范围`、`已移除` 三个数量。
- 底部唯一主操作为“确认范围并进入人员分派”。
- 不提供逐条接受、逐条拒绝或逐条确认按钮。

## 数据与接口

现有 AI 范围草稿接口继续负责生成结果、读取候选和移除候选；现有 `POST /quality/test-requests/:id/scope/cases` 负责把人工从用例库加入的正式用例写入当前提测草稿。前端按 `scopeRevision` 提交批量变更，服务端继续执行 Workspace/项目用例库权限校验和并发校验。

用例库树按需加载模块和用例，避免一次性读取全部用例。加入或移除成功后刷新右侧范围和顶部统计，失败时保留当前本地选择并提示可重试。

## 状态与边界

- AI 分析中保留当前页面结构，显示局部 loading，不清空已有范围。
- AI 分析完成后默认纳入结果；用户只需移除不满意项。
- AI 新用例不自动写入长期用例库，人工保存入口放在节点的次级操作中。
- 范围确认后沿用现有人员分派和快照流程。
- 本次只调整 Web 范围工作台，不新增 MCP/CLI/协议能力；本地 Agent 继续消费确认后的测试计划和执行接口。

## 验收标准

1. 页面能同时看到可选用例库树和本次提测范围树。
2. AI 推荐结果首次加载后已在右侧，用户可以直接批量移除。
3. 用户可以按用例库、模块和单条用例加入或移出范围。
4. 列表中不存在步骤、预期结果、测试数据和匹配理由等详情文本。
5. AI 新用例有清晰标记，保存到长期用例库需要人工操作。
6. 范围确认和后续人员分派流程保持可用，相关 Web 测试和构建通过。
