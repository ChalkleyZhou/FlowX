# 提测范围单列表交互设计

## 背景

当前提测详情的范围工作台同时展示左侧用例树、右侧范围穿梭列表和下方已确认快照。用户需要在多个区域之间切换，无法快速回答“当前有哪些用例、哪些会被提测、某条用例具体怎么测”。

## 目标

1. 用例库树用于快速定位和筛选，保留 Workspace 共享库、项目库、模块层级。
2. 用例列表只有一个事实来源，勾选状态直接代表本次提测范围。
3. AI 推荐默认已纳入，用户通过取消勾选快速删除不满意项，通过勾选快速补充用例。
4. 列表保持高密度，只展示标题、优先级、来源和选择状态；点击用例后按需查看详情。
5. 移除提测范围页下方重复的“已确认的测试范围”明细，确认后直接进入分派。

## 交互设计

### 页面结构

- 顶部显示“AI 提测范围”、已选数量、AI 推荐数量和已移除数量。
- 左侧为可展开树：用例库 → 模块 → 用例。树节点支持搜索、勾选和批量选择。
- 右侧为统一用例列表，提供“全部 / 已选 / AI 推荐”筛选和标题搜索。
- 列表行显示标题、模块路径、优先级、AI 新用例标记；已选状态使用复选框表达。
- 点击列表行（不点击复选框或保存按钮）打开详情抽屉，展示步骤、预期结果、测试数据和来源信息。
- AI 新用例保留“保存到用例库”操作，默认只存在当前提测草稿；保存动作仍由人工触发。
- 底部只保留轻量操作栏：已选数量和“确认范围并进入分派”。不再渲染已确认快照列表。

### 数据行为

- 进入页面时加载 AI 范围草稿和用例库树的首层。
- 展开用例库或模块时按需请求下一级数据，避免首次加载所有用例。
- AI 草稿中的非 EXCLUDE 候选默认进入已选集合。
- 取消已选用例调用现有范围草稿移除接口；勾选正式用例调用现有补选接口。
- 搜索、树筛选和“已选/AI 推荐”只改变列表视图，不改变范围数据。
- 确认时继续使用现有 `scopeRevision` 校验和 `prepareTestRequest` 接口。

## 非目标

- 不修改提测范围 API、数据库模型、快照语义或分派流程。
- 不自动把 AI 新用例保存到长期用例库。
- 不新增本地 Agent、MCP、CLI 或共享协议能力。
- 不在列表中常驻展示步骤、预期结果等详情。

## 验证

- Web 组件测试覆盖：AI 推荐默认勾选、树筛选与补选、取消勾选移除、筛选切换不丢选择、点击行查看详情、保存 AI 新用例、确认范围。
- Web build 验证 TypeScript 和打包产物。
- 文档同步更新 `docs/user-manual.md` 及 `apps/web/public/user-manual.md`。
- 本地适配结论：复用现有 API 和确认后的测试计划/执行接口，不需要修改 `flowx-local`、MCP、CLI 或 `@flowx-ai/protocol`。
