# 测试设计页轻量化改造设计

## 背景

当前“测试设计”页同时承担用例库/模块选择、AI 候选逐条处理、设计确认、提测入口和执行报告提示。用户进入页面后无法判断当前要完成的任务，且这套流程与新的“创建提测后由 AI 自动生成范围、人工删除、确认并分派”方案重复。

## 目标

将测试设计页收敛为 AI 分析来源页。页面只回答三个问题：AI 使用了哪些研发输入、当前分析产出了什么、下一步如何发起提测。用例范围的删改、确认和人员分派全部在提测详情完成。

## 交互设计

1. 页面标题改为“AI 测试分析”，副标题展示项目、版本和需求上下文。
2. 页面顶部只保留刷新和重新分析两个操作。已绑定提测时显示“查看提测详情”。
3. 用单一流程条展示“AI 分析 → 发起提测 → 范围确认与分派 → 执行与报告”，当前页只高亮 AI 分析。
4. 用“分析输入”卡片展示需求、技术方案、Spec & Plan、研发提交记录、代码差异和代码库上下文的来源摘要；不提供库/模块选择控件。
5. 用“分析结果”卡片展示功能候选数量、冒烟数量、未覆盖验收点和生成状态。只展示摘要，不展示逐条候选编辑按钮。
6. 主操作只有“发起提测”：
   - 未绑定提测时进入提测创建弹框，并带入项目、版本、需求和已完成研发工作流；
   - 已绑定提测时显示“查看提测详情”；
   - AI 分析未完成或失败时，按钮根据状态显示等待/重试提示，不能误导用户进入执行。
7. 删除旧的“选择用例范围”“处理建议与补选”“确认测试设计”“确认本页冒烟”等页面操作和分页列表。
8. 保留失败状态和诊断编号，支持重新分析；保留未覆盖验收点摘要用于追溯。

## 数据与兼容

本次只调整 Web 展示和入口，不改变测试设计 API、候选数据和提测范围 API。旧测试设计详情链接继续可访问；已有确认测试设计仍展示分析摘要，并可进入已有提测详情。

## 验证

- 更新测试设计页测试，验证不再出现用例库/模块选择和逐条确认入口。
- 验证 AI 输入摘要、候选统计、失败重试和发起提测链接。
- 运行 Web 质量页面测试和 Web build。
