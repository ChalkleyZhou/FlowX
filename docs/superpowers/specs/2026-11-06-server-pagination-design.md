# 全站服务端分页设计（已实施）

## 目标与验收边界

所有用户可浏览的业务记录列表采用服务端分页，首屏和翻页只查询、传输当前页；不再先拉取全部数据后通过 `filter`、`slice` 实现分页，也不通过循环拉完所有页来维持原有页面实现。

覆盖 Web 页面、详情中的可增长子列表、弹窗和下拉选择器，以及 MCP/CLI 对应的记录发现入口。静态枚举、固定能力清单、单条记录自身的结构化字段不作为独立记录列表分页。业务执行、报告聚合等确实需要处理完整范围的服务端内部计算不受 UI 分页限制，但浏览接口不能借这些计算返回全部明细。

## 方案比较与选择

1. **推荐：服务端分页并同步全部消费者。** 真正限制数据库读取和网络响应，所有搜索、统计及选项行为一致；涉及 API、Web 和本地包，需要统一验收。
2. 仅给页面增加翻页按钮。改动小，但仍下载全部记录，不满足本次要求。
3. 按数量硬截断列表。能限制响应，但用户无法继续浏览，且会遗漏可操作记录，不采用。

## API 与查询约定

- 普通记录列表统一接收 `page`、`pageSize`，默认第 1 页、每页 20 条，最大每页 100 条。校验有限正整数，拒绝负数、小数、非法文本及超大页大小；既有更严格限制可继续保留。
- 普通分页响应统一包含 `{ items, total, page, pageSize, totalPages }`；空集合的 `totalPages` 为 1。HTTP 事件浏览同样使用页码；内部执行同步保留既有游标机制。
- Prisma 查询先构造组织、权限和业务筛选，再将同一条件用于 `findMany` 和 `count`；数据查询必须带 `skip/take` 或等价游标限制，不能查询全量后切片。
- 排序延续业务现状，并追加唯一 ID 作为并列排序键，避免相同时间记录翻页重复或遗漏。偏移分页不承诺跨多次请求的数据快照；刷新按当前数据重新查询。
- 页码超过当前结果范围时，返回可识别的空页和真实总数，由客户端回到最后有效页后重查；删除最后一条和筛选变化都覆盖这一流程。
- 数量卡片由服务端聚合提供。原有项目范围统计与当前筛选计数分别建模，不得用当前页条数代替全量统计。
- 列表响应只含列表所需字段、摘要、计数和必要的固定关系；大型正文和可增长子集合通过详情或子列表接口按需读取。

## Web 交互

- 复用统一分页组件，显示总数、当前页、总页数及上一页/下一页；保留已有每页 20 条的需求和看板体验，其他页面可采用更小的页大小，按界面标注展示。
- 翻页触发服务端请求。筛选、搜索、项目变化回到第一页；页码和筛选保留在 URL，沿用现有本机筛选记忆规则。
- 搜索采用防抖，处理请求竞态，旧页或旧项目的晚到响应不能覆盖当前结果。
- 初次加载、主动刷新和后台轮询分别建模；有数据时后台刷新保留内容，避免整页闪烁；错误保留可重试入口。
- 下拉选择器使用服务端搜索和“加载更多”，不在初始化时自动遍历所有页。选中值不在当前页时仍通过 ID 解析并显示。
- 用例勾选跨页保留明确的 ID；“选择当前页”与“选择全部匹配项”语义明确。执行、确认和报告以明确选中范围或服务端完整业务范围为准；“确认本页冒烟”明确仅处理当前页。

## 本地适配与兼容

**结论：需要适配。** 影响 `packages/flowx-local/src/mcp.ts` 中项目、研发任务、用例库/模块/用例、本地测试及冒烟任务等列表工具，以及依赖其数组响应的 CLI、Adapter 和 Skill 模板；共享分页契约检查 `@flowx-ai/protocol`。

- 工具 schema 增加分页/搜索参数并实际透传，结果必须保留总数、页码或下一页游标；工具说明引导按需翻页，不自动加载所有页。
- 需求/缺陷混合任务列表需要在 API 按统一排序分页，不能各取一页后在本地拼接成不完整页面；OpenDesign 候选作为独立分页集合，不能因主任务翻页而遗漏。
- 默认响应也必须有界。不得为了旧客户端兼容继续保留默认全量查询，也不得将第一页伪装为完整数组。
- 现有数组响应改为分页对象属于破坏性契约变化。发布时同步 API/Web 和本地包，明确支持版本、升级顺序及 `flowx-local update`、IDE MCP 重新加载要求；为实际受影响的旧客户端提供可识别的升级错误。具体识别方式须依据现有客户端版本/能力机制确定，并在实施计划中列出，不能假定旧客户端能解析新对象。
- 分页只影响读取和发现，不改变领取、授权、状态机、幂等或人工确认规则。完整执行上下文与记录浏览分页分开建模，避免把未展示项误判为不存在或已完成。

## 实施顺序与验证

1. 补齐接口/消费者清单、兼容识别方案和共享分页契约测试。
2. 建立分页参数、响应类型、查询约定与通用 Web 控件，优先迁移需求、工作流、缺陷和问题，再迁移项目/工作区、简报、配置及管理列表。
3. 迁移质量模块独立列表和详情子列表，补齐选例、候选、轮次与报告的完整范围语义。
4. 迁移项目上下文、选择器、排期以及 MCP/CLI/Adapter/Skill，移除浏览链路中的全量兼容回退。
5. 同步 README、系统设计、分页专题说明、用户手册、本地 Agent 指南、镜像及 CHANGELOG。

先补边界测试再改实现：默认请求有界、第二页数据独立、稳定排序、组合筛选、统计范围、组织/权限隔离、无效参数、空页、删除回退、失败重试、跨页选中、请求竞态和真实 MCP 请求/响应解析。测试需断言查询在数据库层限量，而不只验证响应长度。

最终执行 API/Web/local/protocol 的相关测试及构建、`pnpm check`、`git diff --check` 和两份手册镜像 `cmp`；浏览器检查至少覆盖一条普通列表、一条质量列表和搜索选择器的请求参数及翻页行为。未完成的模块必须逐项披露，不宣称全站完成。
