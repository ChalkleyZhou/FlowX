# 原型 ZIP 导入

已有 OpenDesign 或其他工具导出的原型时，可直接使用「需求 → 创建需求 → 已有原型」，选择项目、发布版本、ZIP 和 Codex / Cursor。发布版本默认带出项目当前版本，也可改选；切换项目后重新带出对应当前版本，无版本时引导到项目设置，选择后才能上传。目标可选，不要求先重写 PRD。

项目详情的「需求列表 → 新建需求」也支持原型 ZIP：填写标题、选传 ZIP 即可，自动带入弹窗显示的当前版本。无需另外创建普通需求，上传后自动整理并接入工作流，无需确认。失败保留标题和文件，移除 ZIP 后可恢复普通创建。快捷入口沿用需求页保存的 Codex / Cursor 偏好；未设置时使用服务器默认执行器。

## 必要路径

1. 上传后自动创建需求，后台识别材料并生成需求、验收标准、设计说明、来源依据和推断。
2. AI 整理成功后由服务端自动保存资料并启动工作流，仓库准备完成后接续 Spec & Plan；用户无需填写问题或确认。浏览器展示进度，成功后自动进入流程。
3. 失败直接显示原因，原材料保留。统一点击「重新导入」即可沿用当前 ZIP，或先选择新的 ZIP；AI 也可以同时切换。换包按新 ZIP 完整替换分析材料，旧包和历史版本仍可下载，不会把已删除的旧文件混进新分析。接续失败时重试复用已整理资料；换包会重新分析。
4. 原型与来源材料按需展开查看。旧「等待确认」记录打开后自动接续，不再展示确认表单。

AI 提出但未回答的问题保留在 `brief.openQuestions`，推断保留在 `inferences / brief.assumptions`，不擅自采用建议为人工已确认规则。导入不增加人员分配、任务领取或设计审批。导入成功表示资料已整理并接入流程，后续技术方案和研发仍按原有工作流推进。

## 材料与预览范围

| 材料 | 当前处理 |
| --- | --- |
| HTML | 保留原始页面，优先 `index.html`；内联包内 CSS、图片、字体，保留可支持的脚本交互和包内页面导航 |
| 图片 | 保留预览和文件信息；本轮不向 AI 提供视觉理解，不能声称已读懂图片细节 |
| Markdown、文本、JSON、CSV | 提供有限文本摘录和文字预览 |
| JS、TS、CSS 等源码 | 提供有限摘录；HTML 引用的静态模块可受限打包，不安装依赖、不执行项目命令、不启动开发服务器 |
| PDF、Word | 仅保存附件，未提取正文；请附 HTML、Markdown 或文字说明 |
| 其他资源 | 保存在原包和清单中；不保证运行或预览 |

原型在无 same-origin 的 sandbox iframe 内运行，可信父外壳通过 CSP 阻断原型自身外部导航；新窗口也保留该外壳。常规联网资源、请求、表单与嵌套框架受限制，不提供后端 API；需要网络、动态加载、Worker 或构建工具的原型可能无法完整运行。它适合核对页面与本地交互，不能代表真实系统功能已实现。不要在原型中填写真实凭据。

AI 依据有界清单和文本摘录分析，整体上下文上限 90,000 字符、单文件摘录最多 6000 字符；截断内容不代表已分析。问题与来源路径经过校验，但仍需人工核对实际业务范围。

## 体积限制与保存

- ZIP 最大 20 MiB，单文件最大 5 MiB，合并后最多 1500 文件、60 MiB。
- 拒绝越界/绝对路径、符号链接、特殊文件、加密包、重复路径和损坏 ZIP。
- 单页隔离预览最大 12 MiB。进入工作流的设计页面单页最多 5 MiB、总体最多 24 MiB，超过预算时展示提示页，可回到需求查看或下载原包。
- 原材料私有保存到 API 工作目录 `.flowx-data/prototype-imports/{id}/{materialRevision}`。各次 ZIP 与清单按材料版本保留；替换包只使用当前新包生成清单，不继承旧文件。材料版本和草稿 revision 分离，编号不一定连续。
- 数据库记录包含组织关联、分析、历史答案与资料落库时间；自动导入不记录虚构的人工确认人；下载和预览需登录且属于该组织。

## API 与部署

新增 `PrototypeImport` 表，与 Requirement 一对一关联。已有部署升级前备份数据库，按仓库现有流程生成 Prisma client 并同步 schema；相关 migration 为 `20261022090000_prototype_import`。确保 API 运行数据目录持久化并随 SQLite 一起备份。Docker 继续使用现有 schema 同步和运行目录卷，无新增环境变量。

| 接口 | 用途 |
| --- | --- |
| `POST /prototype-imports` | multipart `file`、`projectId`、可选 `title`、`versionId`、`goal`、`aiProvider`，创建并后台分析 |
| `GET /prototype-imports/:id` | 状态、材料清单、分析结果与 workflowRunId |
| `PATCH /prototype-imports/:id` | `revision`、可选 `analysis`、`answers`，保留的旧草稿兼容接口，新入口不使用 |
| `POST /prototype-imports/:id/analyze` | 同上及可选 `feedback`、`aiProvider`（`codex` / `cursor`），重试导入；旧等待确认记录无反馈时直接复用资料 |
| `POST /prototype-imports/:id/files` | multipart `file`、`revision`、可选 `aiProvider`、`replace=true`，使用新包替换材料并重新分析 |
| `POST /prototype-imports/:id/confirm` | 保留的旧确认兼容接口，新入口不调用 |
| `GET /prototype-imports/:id/preview?path=...` | JSON `html` 和 `warnings`，用于 sandbox 预览 |
| `GET /prototype-imports/:id/source?revision=...` | 授权下载对应上传版本的 ZIP |

`title` 用于初始需求标题，未传时沿用 ZIP 文件名；未提供 `goal` 时标题同时作为 AI 整理线索。最终标题使用 AI 整理结果。`versionId` 显式传入时必须属于该项目，非法或跨项目版本在保存原型包前拒绝；省略时兼容使用项目当前版本（包括历史无版本导入）。需求页原型上传必须选择发布版本；项目快捷入口必须有当前版本。两处均显式提交显示的版本，避免上传过程中项目版本切换导致归属变化。

重新导入指定 `aiProvider` 时，与状态及 `revision` 原子更新导入记录；省略则沿用已有执行器。选择新 ZIP 时使用完整替换模式，后台从已保存记录解析对应组织凭证，后续工作流使用该执行器。非法执行器、跨组织请求、旧修订或处理中重试均被拒绝。认证错误只回传固定文案；服务端记录导入 ID、修订、执行器与错误分类，避免泄露上游凭证或原型内容。

## 已进入研发后的原型变更

需求详情的「需求变更」入口可选择新的 ZIP。选包后只显示「重新走流程」，变更说明可留空，平台默认沿用当前流程的 AI，也可切换 Codex / Cursor。平台独立保存新 ZIP，后台完成 AI 整理后将不可变分析快照绑定到新流程；原需求、原型导入记录、旧工作流和旧产物继续保留。分析失败或仓库冲突时材料保留，列表显示失败原因并可点击「继续启动流程」。原型变更包可从变更记录下载，下载仍按组织权限校验。

服务端完成 schema 和来源校验后，以 CAS revision 更新导入记录并保存 Requirement、简报和设计产物，再调用既有 WorkflowService 创建流程。工作流的 `REQUIREMENT_INTAKE` 保存不可变导入快照，仓库 grounding 后接续 Spec & Plan。自动导入的 `confirmedBy` 为 `null`，`confirmedAt` 表示资料落库时间；历史人工确认快照保持兼容。接续前后不允许普通入口绕过未完成导入；失败重试替换同一需求的导入产物，不新增需求副本。

状态保留 `ANALYZING / WAITING_CONFIRMATION / FAILED / CONFIRMED` 以兼容旧记录。新导入不会停在 `WAITING_CONFIRMATION`；`CONFIRMED` 表示资料已自动落库，只有取得 `workflowRunId` 才显示导入成功，否则继续展示接续进度，接续异常变为 `FAILED`。异步任务采用当前单进程模型，服务重启会将未完成导入标为可重试失败；不具备多实例持久任务队列。Codex / Cursor 需使用现有可用 AI 配置，不支持的 executor 会明确失败，不返回伪造分析。
