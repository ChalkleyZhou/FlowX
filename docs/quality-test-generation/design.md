# 测试设计与用例确认交互设计

## 设计目标

在不阻塞开发执行的前提下，让测试人员能够高效完成用例生成、现有用例比对、优化确认和本次冒烟范围确认，并在提测前清楚看到剩余门禁。

## 信息架构

### 工作流详情

在 Spec & Plan 阶段之后展示“测试设计”并行任务入口。它不是研发主流程的串行阶段，不改变执行开发、AI 审查和人工确认的阶段顺序。

入口显示：

- 当前状态：未开始、生成中、待处理、待确认、已确认、已过期、生成失败。
- 当前修订号和最近更新时间。
- 功能用例数量、待优化数量、冒烟用例数量和未覆盖项数量。
- “生成测试用例”“查看测试设计”“刷新影响分析”操作。

### 测试与质量 / 提测管理

新增提测详情页：`/quality/test-requests/:id`。

详情页包含以下页签：

1. 测试设计：覆盖摘要、候选决策和确认状态。
2. 冒烟用例：本次动态生成的冒烟用例。
3. 测试范围：已冻结的功能用例和冒烟快照。
4. 执行轮次：冒烟、完整测试和 Bug 回归轮次。
5. 变更记录：生成、编辑、确认、过期和入库记录。

## 核心页面

### 测试设计总览

页面顶部使用紧凑状态栏展示：

- 来源：需求、项目版本、工作流、PRD、设计和 Spec & Plan。
- 来源是否为最新版本。
- 当前修订状态和确认人。
- 提测门禁状态。

主体按工作效率组织，而不是使用多层卡片：

```text
覆盖概览
  功能点  主流程  异常路径  权限  数据边界  未覆盖项

候选处理
  [全部] [复用] [优化] [新增] [不纳入] [待处理]
  ┌──────────────────────────────────────────────────┐
  │ 场景 / 来源 / 建议 / 匹配度 / 处理结果 / 操作       │
  └──────────────────────────────────────────────────┘

冒烟用例
  本次改动关键路径及执行顺序

底部固定操作区
  待处理 3 项  未覆盖 1 项       保存草稿  确认测试设计
```

### 候选用例列表

每条候选显示：

- 场景名称和优先级。
- 覆盖的需求规则、验收标准或设计状态。
- 建议动作：复用、优化、新增或不纳入。
- 匹配到的现有用例库、模块、编号、版本和匹配置信度。
- AI 选择理由和风险说明。
- 当前人工处理结果。

列表支持按建议动作、处理状态、优先级、覆盖对象和用例库筛选。

### 复用确认

右侧详情面板展示现有用例完整内容、本次适用理由和关联覆盖对象。

用户可以：

- 确认复用。
- 改为优化。
- 改为新增。
- 标记不纳入并填写原因。

### 优化确认

优化面板默认使用字段级差异视图：

- 左侧为当前正式版本。
- 右侧为建议新版本。
- 标出前置条件、步骤、预期结果、优先级和标签变化。
- 显示当前正式版本号，若版本已变化则禁止直接确认并要求重新比对。

用户可以编辑建议内容，然后选择“接受优化”或改为其他处理方式。

### 新增用例确认

新增用例面板允许编辑所属用例库、模块、编号、标题、优先级、前置条件、步骤、预期结果和标签。

默认写入当前项目库。只有具备 Workspace 用例管理权限的用户才能改为共享库。

### 冒烟用例确认

冒烟页签不展示历史冒烟套件，只展示本次改动生成结果：

- 冒烟目标及其关联改动。
- 建议执行顺序。
- 每条用例的前置条件、最短步骤和关键预期结果。
- 阻断级别：失败后是否停止后续完整测试。

用户可以拖动排序、编辑、增加和删除。删除到零条时，界面要求选择“本次无适用冒烟场景”并填写原因。

### 覆盖矩阵

覆盖摘要使用二维矩阵帮助检查遗漏：

| 覆盖对象 | 复用 | 优化 | 新增 | 冒烟 | 状态 |
| --- | ---: | ---: | ---: | ---: | --- |
| 验收标准 | 数量 | 数量 | 数量 | 数量 | 已覆盖/待处理 |
| 主流程 | 数量 | 数量 | 数量 | 数量 | 已覆盖/待处理 |
| 异常路径 | 数量 | 数量 | 数量 | 数量 | 已覆盖/待处理 |
| 权限与角色 | 数量 | 数量 | 数量 | 数量 | 已覆盖/待处理 |
| 数据边界 | 数量 | 数量 | 数量 | 数量 | 已覆盖/待处理 |

选择某一行后，候选列表只展示对应覆盖对象。

## 状态与操作

```text
NOT_STARTED
  -> GENERATING
  -> WAITING_REVIEW
  -> WAITING_CONFIRMATION
  -> CONFIRMED

GENERATING -> GENERATION_FAILED -> GENERATING
WAITING_REVIEW -> GENERATING（重新生成）
WAITING_CONFIRMATION -> WAITING_REVIEW（继续修改）
CONFIRMED -> STALE（来源或实际改动变化）
STALE -> GENERATING / WAITING_REVIEW（人工刷新差异）
```

- `WAITING_REVIEW`：存在未处理候选或未覆盖项。
- `WAITING_CONFIRMATION`：所有候选已处理，允许最终确认。
- `CONFIRMED`：当前修订可用于提测。
- `STALE`：来源版本变化，禁止用于新的提测快照。

## 提测门禁展示

发起提测和提测详情页统一展示门禁清单：

- 研发工作流已完成。
- 测试设计已确认且未过期。
- 功能测试用例已处理。
- 冒烟用例已确认，或已确认无冒烟原因。
- 覆盖检查已完成。
- 正式用例更新和提测快照已冻结。

未通过项显示明确原因和直达处理位置的操作，不使用只有错误文案的阻断弹窗。

## 重新生成与差异刷新

- PRD、设计或 Spec & Plan 修改后，顶部显示“来源已变化”，原确认状态变为已过期。
- 用户可以选择“完整重新生成”或“仅分析变化”。
- “仅分析变化”保留已经确认且未受影响的人工决策，只把受影响候选恢复为待处理。
- 开发完成后若实际改动与 Spec & Plan 存在差异，提测门禁显示“实际改动待刷新”。
- 每次刷新都生成新修订，旧修订保持只读。

## 空状态与失败状态

- 上游文档未确认：说明缺少哪个产物，并提供回到工作流的入口。
- 用例库为空：仍允许生成新增用例，但明确提示没有可比对的现有用例。
- 未发现新增或优化需求：允许全部复用，但仍需确认冒烟结果。
- 生成失败：保留失败原因和重试入口，不清空上一份可用草稿。
- 无冒烟场景：要求人工填写原因并确认。
- 匹配结果冲突：展示最新用例版本并要求重新比对。

## 权限建议

- 查看：项目成员。
- 生成和编辑草稿：项目成员中的研发、产品和测试角色。
- 确认测试设计：测试负责人或项目管理员。
- 更新项目用例库：测试角色或项目管理员。
- 更新 Workspace 共享库：Workspace 管理员或被授予共享用例管理权限的成员。

## 响应式要求

- 桌面端使用高密度表格和右侧详情面板，避免频繁跳页。
- 窄屏下候选列表切换为分组行，详情面板改为全屏抽屉。
- 固定底部确认区不得遮挡最后一条候选内容。
- 长标题、步骤和预期结果必须换行，不得挤压状态与操作列。
